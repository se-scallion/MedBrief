# 问诊资料卡 · 逻辑规格 v3-final（可直接交给 AI 改）

> 读者：**门诊医生**（血液科）。使用者：**患者 / 家属 / 代诊人**。
> 介质：**A4 PDF（打印 & 微信传阅为主）+ 自包含 HTML（手机/电脑浏览器，可点原件）**。
> 目标：把跨院、跨时间的多份检查单，变成 **第 1 页 1 分钟看懂病情 + 第 2 页全量可查不漏项 + 第 3 页趋势变化**。
>
> 版本：**v3.3**（2026-11-14：第 1 页新增「疾病标签与安全基线」、抬头瘦身、黑白打印友好）。
> v2 → v3 的实质变化：数据地基（字段清洗 + code 覆盖）→ 1+1+1 分页 → P0/P1 分层 → 最新状态口径 → 危急值 →
> 时效提醒 → 原件按钮 → 材料清单聚合 → NT-proBNP 别名归一。

## 零、先读这一节（血的教训，改之前必看）

1. **真实数据里有 9 行「三列整体左移」**：`名称(含着真值) | 值=参考区间 | 参考区间=单位`。
   例：`{"name":"凝血酶原时间（P12.2个T）","value":"9.8-12.1","refRange":"sec"}` 的真义是 `PT=12.2，参考 9.8-12.1，单位 sec`。
   后果：卡面「值」显示的是参考区间、参考区间显示的是单位；且 `sec` 不是区间 → 无法判高低 → `status=unknown` →
   **既不进异常项、也不报错**。修复在 `lib/labClean.mjs` 的 `repairColumnShift()`，读侧生效，不改真实数据。
2. **code 覆盖率曾经只有 6/204**（且全部来自病理 FCM 适配器）——原因是新导入工作流那条路径根本没写 `code`。
   现在读侧统一用 `classifyAnalyte()` 补（覆盖率 **204/204 = 100%**），`ANALYTE_CATALOG` 仍是**唯一登记处**。
3. **模糊匹配会串码**：`红细胞平均血红蛋白含量`(MCH) 含 `血红蛋白` 会冒充 Hb；`有核红细胞占有核细胞比例` 会冒充 RBC。
   所以 `classifyAnalyte` 的「包含匹配」只在调用方显式传 `{ loose: true }`（仅对已标 `nameDirty` 的脏名）时启用。
4. **不要拿 `data/reports.json` 当断言靶子**：那是活数据（3 小时内 49→54 份）。断言一律对
   `tests/fixtures/card-snapshot-v3.json`（脱敏冻结快照，`tools/make-card-snapshot.mjs` 生成，自带脱敏自证）。
5. **OCR 会把参考说明整段拼进项目名**。实测唯一残留脏名是 NT-proBNP：
   `P急性心衰急性心衰按年龄分层：<50岁：>450pg/ml50-75岁：900pg/ml>75岁：>1800pg/ml`。
   NT-proBNP 是心功能关键项（蒽环类化疗必看），**不能因为名字脏就落进「其他项」** →
   `lib/labClean.mjs` 的 `NAME_ALIASES` 做硬归一：命中 `proBNP / proBN / 「急性心衰+pg/ml 阈值」` → 规范名 `前体NT-proBNP`，
   code `NT_PROBNP`，值 `<300pg/ml-非` → `<300`，并留痕 `name-alias`。**只做化验学等价还原，不猜任何临床结论。**

## 二、处理规则（改任何一条必须同步改 `tests/verify-card.mjs`）

1. **读侧清洗**（`lib/labClean.mjs`，幂等）：列左移还原 → 单位/区间串位 → value 尾巴噪声 → 单位写法归一 →
   名称清洗（剥数值/箭头字/定性结果/圈号/OCR 截断）→ **名称别名硬归一**（NT-proBNP）。
   约束：干净行零改动；固有编号（`CO2`/`pCO2`/`CD34+`/`白介素6`/`P190型`）**不得**剥。
2. **code 优先归并**：有 `code` 用 `code`，无则退回 `name`。`code` 是去重 / 趋势聚类 / 危急值判定的唯一键。
3. **判定高低**：① 先认报告自带箭头/定性 → ② 再按参考区间比 → ③ 区间非法（`high < low`）置空不猜。
   颜色：高=红 `↑`、低=绿 `↓`。
4. **最新状态口径**：每个 `code` 只判**最近一次**是否异常（历史波动交给趋势页）。
   **不做**「近 14 天曾危急」提示（真实数据近 14 天 0 份报告，无法验证）。
5. **P0 / P1 分层**（`lib/cardPolicy.mjs` 的 `P0_CODES`）：
   - **P0 展开**：血常规全组、凝血、肝肾功电解质、炎症（CRP/PCT/IL-6/NT-proBNP）、骨髓/流式/MRD/遗传、铁代谢、血气乳酸，
     **以及尿潜血 / 尿白细胞 / 尿红细胞（永远 P0，不按报告类型一刀切）**；
   - **P1 折叠**：其余（尿胆原/酮体/尿糖/比重/镜检其他、血气偏差、血型/血清学/病原、粪便）。
     折叠形式：一行摘要「另有 N 项非核心异常（组名…），见第 2 页」。
6. **排序**：危急值优先 → `measuredAt` 新→旧。
7. **危急值**（`CRITICAL_RULES`，阈值可配）：`WBC<1.0 或 >50`、`ANC<0.5`、`Hb<60`、`PLT<20`、`FIB<1.0`、`Lac>4.0`、`K+<2.8 或 >6.0`。
   命中 → **置顶 + 浅红底纹 + 「危急」微标**，并强制升入 P0。
8. **全部指标（第 2 页）**：按 `code` 去重取最新，**三栏并排**（`table-layout:fixed` + `nowrap`，日期以 7px 灰字内联在参考列后），
   **100% 不漏项**。
9. **趋势（第 3 页）**：同 `code` 且单位归一后一致、出现 ≥2 次才画。**白名单制**：只画
   `WBC / NEUT_ABS / Hb / PLT / LDH / FIB / D_DIMER / PCT / CRP / HS_CRP / BM_BLAST_PCT / MRD`，
   其余（MCH、MCHC、PDW、中性粒% 等次要参数）**一律不上图**（不是排后面，是不出现）。
   - **X 轴必须左旧右新**（2026-11-14 修：原来降序画，折线是倒着走的，属严重临床误导）；
   - **只收有效数值点**（定性值「阴性/阳性/未见」不得入图）；同一天多份报告只取当天最后一条。
   - **跨院参考区间不一致** → 不画单一绿带，改 `⚠️ 跨院参考区间不同` + 列出各院区间；
   - **单位确实无法统一** → 不硬拼，进「未绘制（单位不一致）」说明。
10. **缺项**：`REQUIRED_BASICS`（WBC/Hb/PLT/**ANC**/PT/APTT/FIB/LDH）缺失时，卡面显式写「未提供：…」。
11. **时效提醒**：最近一次**有指标**的报告超过 `STALE_DAYS=90` 天 → 第 1 页「核心异常项」标题下方琥珀色警示：
    `⚠️ 最近一次有指标的化验为 YYYY-MM-DD（距今 N 天…），请注意时效性`。数据新鲜时不得误报。
12. **材料清单不进纸质件**（2026-11-14 用户口径：纸质里放材料清单没意义）：
    卡片第 2 页**只有「全部指标」**，按临床大类分组（血常规及骨髓 / 凝血功能 / 生化与肝肾功 / 炎症与免疫 / 尿便与血气 / 其他感染筛查 / 其他）、
    组内双栏、字号 10px、项目名**允许换行不截断**。材料清单与原件回看只在应用内「报告库」页承载。
    （历史实现保留说明）原聚合索引口径：
    - 每组一行：`编号 · 月-日 · 医院 · 化验 4 / 影像 1 · 4 份 · 19 项`；
    - **卡面不得有任何原件按钮／超链接／表单控件**（唯一允许的交互是顶部「打印 / 存 PDF」）。理由三条：
      ① 打印件上点不了；② 卡片是自包含 HTML，另存/转发后 `/api/intake/blob/...` 是死链，比没有更糟；
      ③ 真要回看原件，正确位置是应用内「已导入的报告」列表（有编号、有上下文）；
    - 0 指标的报告组显示 **「仅原件」**，并在表下用图例写明 **「仅原件 = 未结构化（仅存原件）」**，
      **绝不许出现「0 项」**（会被读成解析失败丢数据）。
13. **页数策略**：目标 3 页（正文 1 + 归档 1 + 趋势 1）。
    **极端情况下（累计 150+ 份、全部指标自身就超一页）允许自然分页（3 → 4 页），绝不为了卡死 3 页而截断或丢指标。**
14. **冲突与留痕**：`valueConflict` 数值后加 `*`；`nameDirty` 项目名后加 `?`；页脚各一行说明。
15. **红线**：只陈述数值、日期、判定、趋势与出处；**绝不写诊断结论、治疗建议或预后判断**。

### 2.5 第 1 页顶部「疾病标签与安全基线」（v3.3，`buildSafetyBaseline()`）

只提取、不推断；抓不到一律写「未录入 / 待核」，绝不生成数据里没有的结论。

| 格 | 内容 | 数据来源 | 实测注意 |
|---|---|---|---|
| 分子与高危基因 | BCR::ABL1 / TP53 / KMT2A / IKZF1 / MRD / 原始细胞 / CD34+ / 融合基因 / 核型 / 突变 | `DISEASE_TAG_PATTERNS` | **阳性写在 `status` 里、`value` 为空**（BCR::ABL1 实测如此），必须读 status |
| 初诊基线 | WBC / LDH 的**初诊值 + 峰值 + 最新值** | `BASELINE_CODES`，按 code 聚合 | 「白细胞」与「白细胞计数」是两个名字同一项，按名字会算重 |
| 治疗安全基线 | 血型 ABO/Rh、乙肝/丙肝/HIV/梅毒、基础病、过敏、在用药 | `BLOOD_TYPE_CODES` / `INFECTION_CODES` / `patient.comorbidities|allergies|medications` | Rh 空 →「待核」；**Rh 阳性渲染 `Rh(+)`、阴性 `Rh(−)`**；四项传染病**都查到且都阴性 → 压成一行「传染病四项 均阴性（日期）」**，有阳性或任一项缺 → 逐项列；传染病 value 空 →「未录入」，**不得写「阴性」** |
| 近期治疗节点 | 方案/天数、输血/升白、骨穿结论 | `patient.clinicalContext` | 未填显示「未录入」 |

**伴随病史三项（2026-11-14 用户口径）**：基础病 / 过敏史 / 在用药在录入页各是一个「无 / 有」开关，
**默认「无」**，选「有」才展开文本框；选「无」或没填 → 卡面**整项不出现**（不写「无」也不写「未录入」）。
血型与传染病**不适用**此规则：它们必须显式展示，空值写「未录入 / 待核」。

### 2.7 其他版式口径（v3.3）

- **抬头瘦身**：只留「姓名 性别 年龄 + 一句话诊断 + 阳性基因徽章」；`指标 N 项 / 异常 K 项 / 生成时间` 全部移除（生成时间移页脚）；
  `subtype` 长串移到安全基线下方的「分型依据（原文）」小字，溯源不断。
- **日期去重**：卡片内只出现一个年份时，日期显示 `MM-DD`；跨年才带年份（`makeDateFmt`）。
- **标题层级**：`h2` 12px / 700 / 左 3px 黑竖条 / 下 1px 黑细线。
- **通俗注释**：第 2 页分组标题后加括号说明（`凝血功能（评估出血 / 血栓风险）` 等，见 `CATEGORY_HINTS`）。
- **家属三问留白**：未填写时显示浅灰提示语（`.ph`，`#c3c7ce`），打印前可手写。

### 2.8 清洗层不变量（2026-11-14 事故后新增，`tests/verify-labclean.mjs` 守）

**定性结果永不静默丢弃。** 事故：v3.2 用「纯中文 ≥2 字 → 说明性短语」判据清空 value，
把 31 个合法定性结果洗成空值（`阴性`×22 / `阳性`×4 / `未见`×4 / `褐色稀便`×1），
后果是第 2 页 10 行空白、第 1 页 `Rh 待核` / `乙肝 HBsAg 未录入` —— 卡面照样 1 页 A4、测试全绿。

| 规则 | 口径 |
|---|---|
| 保留 | 以定性结果词开头（阴性/阳性/未见/neg/色彩描述…）或**整串不含数字**的值 → 原样保留，标 `qualitative`（挡在趋势与高低判定之外） |
| 清空 | 仅当命中「说明性短语」词库（心衰/衰竭/病史/参考值/建议/提示/增高低…）→ 值清空 + `prose-dropped`（实测唯一真例：NT-proBNP 的「慢性心衰」） |
| 名称 | 名称里粘连的结果 token（`（-）`/`（+）`）剥掉后必须能命中 code，否则基线区只能写「未录入」 |
| 单位 | `fI/f1/fi → fL`、`wmol/L → umol/L`（`fI` 曾让血小板平均体积被判「单位不一致」而整项丢趋势） |
| 参考区间 | 去排版噪声：前导 `*`、尾部 `、`（`*Rh血型阴性、` → `Rh血型阴性`） |

### 2.9 第 2 页版式与非病人数据（v3.4，2026-11-14）

- **列宽 44 / 32 / 24、值列允许折行、参考列允许折行**：旧版 52/24/24 + `nowrap` 让 `35（++）umol/L` 溢出压到参考列，
  `Rh（D）血型鉴定` 的参考区间顶到页边被裁。门禁：`tools/card-pdf.mjs` 的 `--assert-clean`（像素级：撞车 / 溢出 / 裁切三类，必须 0 处）。
- **剔除项（白名单，`counts.excluded`）**：
  - `reagentControl` —— 试剂质控行（`内部对照` / `阳性对照` / `阴性对照` / `空白对照` / `质控`，见 `REAGENT_CONTROL_RE`）。
    实测它们曾因 value=阳性 被标 `▲ 高` 混进「其他感染筛查」。
  - `emptyShell` —— 清洗丢弃值（`prose-dropped`）且无定性的空壳行（实测仅 `前体NT-proBNP`）。
  - **不在此列**：value 为空的传染病四项 / Rh —— 它们必须保留并写「未录入 / 待核」。
  - 完整性自洽：`counts.rows`（入库行，不因剔除而变小）== `counts.shown` + 两类剔除之和。
- **趋势白名单**：核心 8 项（WBC/ANC/Hb/PLT/LDH/FIB/D-二聚体/PCT）+ `MPV`（血小板平均体积）**排最末位**，
  只有核心项不足时才补位（用户口径：MPV 修好单位后可以画，但优先级排在最后）。
- **趋势卡不再有底部文字点位行**（2026-11-14 决定）：那行只是把折线再念一遍，且曾与折线方向相反（图上左旧右新、字却右新左旧），
  精确数值在第 1 页「最新值」与第 2 页「全部指标」都有。守卫：`tests/verify-card.mjs`「趋势格只留折线」。

## 六、留给下一位 AI 的开放问题

1. **材料清单已聚合，但全部指标仍会随导入增长**：约 60 份新增后第 2 页自然分页（允许，不截断）。
   若要长期压在 3 页，需要「按医生关注度分页」或「只打印 P0 + 最近 90 天」——**这是产品决策，不是版式问题**。
2. **`value` 里的定性值**（`35（++）`、`WBCl-3`）仍可能被 `num` 解析成数字参与危急值判定，建议给 `qualitative` 行加短路。
3. **血气与生化同名不同轴**（血气 `Hct` vs 血常规 `HCT`）已分 code，但趋势图上可能出现两条相似曲线，需在图上标来源（血气/生化）。
4. `nameInferred`（序号插值补全的名称）目前只在数据里标记，卡面没显示 —— 要不要与 `nameDirty` 共用 `?` 标记。
5. 危急值阈值硬编码在 `lib/cardPolicy.mjs`，是否开放成 `patient.json` 的可配置项（不同医院血库阈值不同）。
