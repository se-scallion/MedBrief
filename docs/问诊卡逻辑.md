# 问诊资料卡 · 逻辑规格（可直接交给其他 AI 优化）

> 读者：**门诊医生**（血液科）。使用者：**家属/代诊人**（拿手机截图来）。
> 一句话：把「另一位患者（病友）」的一堆检查单截图，变成**一页纸**，让医生 1–2 分钟看懂病情。
> 本文是**逻辑与版式的唯一规格**；改版式先改这里，再改 `lib/intakeCard.js`。
> 版本：v2（2026-11-13 按用户口径改版：不脱敏 / 异常项倒序 / 去掉「最新指标」/ 指标压到最后 / 高低红绿+箭头右对齐 / 趋势放最后一页 / 加打印按钮）。

---

## 一、输入数据契约

```jsonc
// buildCard({ reports, mask })   —— mask 默认 false（2026-11-13 用户：给医生看，不脱敏）
reports: [{
  id, createdAt,
  kind: 'lab' | 'pathology' | 'imaging' | 'discharge' | 'drug' | 'unknown',
  reportDate: 'YYYY-MM-DD',      // 报告日期（缺则空串，绝不猜）
  hospital, labName, barcode,    // 抬头事实字段，照抄原件
  source: 'image' | 'text-only', // text-only = 无原图，无法核对，只能当草稿
  fileBlobId,                    // 原件引用（blob 存储 id），有则可显示「原件」按钮
  rows: [{
    name,                        // 项目名（中文优先，可含缩写：血红蛋白 HGB）
    code,                        // 标准码（WBC/Hb/PLT/NEUT_ABS…），无则 null
    value,                       // 原样字符串（保留「<0.01」这类比较符）
    num,                         // 数值（无法解析则 null）
    unit, refRange,              // 参考区间原样串（如 '3.5-9.5' / '126--350'）
    flag: 'high'|'low'|'',       // 高于/低于参考区间
    measuredAt: 'YYYY-MM-DD',    // 采集日期（缺则回退 reportDate）
    nameInferred: true,          // ★名称是按标准序号插值补的，不是识别出来的
    valueConflict: true,         // ★切块边界读出过不同值，已按多数票取用
  }]
}]
patient: { name, sex, age, diagnosis, subtype, stage, hospital, attending, questions:{focus,confirm,nextVisit} }
```

**字段红线**：`name` 照抄原件（缩写与中文都留）；`measuredAt` 缺失时回退 `reportDate`，两者皆空则该行不进趋势段；
`value` 保留原样字符串，`num` 只用于比较与画图。

## 二、处理规则（改任何一条都要同步改断言）

1. **异常判定**：`flag` 由解析层给出（先认报告自带箭头/↑↓，再按参考区间比）。
   参考区间非法（`high < low`）→ 不判定，`flag` 置空，**不猜**。
2. **异常项排序**：按 `measuredAt` **从新到旧**（`b.localeCompare(a)`），跨报告合并。
3. **全部指标**：每个 `name` 只出现一次（取 `measuredAt` 最新那次），按医生阅读顺序（血常规 → 生化 → 炎症 → 凝血 → 其他）。
4. **趋势**：同一 `name` 出现 ≥2 次才画；优先保留关键项（骨髓原始 / MRD / WBC / ANC / Hb / PLT / CRP / LDH），最多 8 条。
5. **缺项声明**：`summary.missingBasics`（如 Hb、PLT 未提供）必须显式写在卡上 —— **「没查」与「没给我」临床含义不同**。
6. **不编造**：任何字段拿不到就留空；`nameInferred` 行要在数据里带标记（当前卡面不单独标注，靠人工校对页把关）。
7. **冲突留痕**：`valueConflict` 行在数值后加 `*`，页脚一行说明「已按出现次数最多的取值采用，原始单据可回查」。
8. **不下结论**：卡面只陈述数值、日期、判定与趋势，**不写诊断结论、不写治疗建议、不写预后**。

## 三、版式（A4 单页 + 趋势单独最后一页）

```
┌ 顶部固定（屏幕）：[打印 / 存 PDF] 按钮（@media print 隐藏）
│
① 抬头：问诊资料卡 · 姓名 性别 年龄
   诊断（含分型）｜ 阶段 ｜ 报告 N 份 / 指标 M 项 / 异常 K 项 ｜ 生成时间
   （可选）未提供：Hb、PLT —— 没查 vs 没给我
│
② 异常项（按时间从新到旧，共 K 项）          ← 医生最先看这块
   表：项目 ｜ 数值(+单位)+箭头 ｜ 参考 ｜ 日期
│
③ 家属三问（横排三格）：本次最想解决 / 想请医生确认 / 下次复查时间
│
④ 全部指标（每项取最近一次，共 M 项）
   两栏并排；每栏表：项目 ｜ 数值(+单位)+箭头 ｜ 参考 ｜ 日期
│
──────── page-break-before: always ────────
⑤ 关键趋势（同项 ≥2 次才显示，共 T 项）
   2×N 网格，每格一张折线图（SVG）：参考区间画淡绿带，异常点红/绿点，X 轴标月-日
│
页脚：冲突说明（若有）+ 免责声明
```

**列定义（四列，比旧版少一列）**

| 列 | 宽度 | 内容 | 规则 |
|---|---|---|---|
| 项目 | 42% | `name` | 照抄，不截断 |
| 数值 | 20% | `value unit` + 箭头 | **数字左贴、箭头贴右**（`justify-content: space-between`）；**高=红 `↑`、低=绿 `↓`**；`*` 表示读数冲突 |
| 参考 | 22% | `refRange` | 原样；空则 `—` |
| 日期 | 16% | `measuredAt` | 空则 `—` |

**已删除**：旧版的「判定」列（红/绿文字）—— 判定已合并进「数值」列的箭头与颜色；
旧版的「最新指标」段 —— 异常项已按时间倒序，信息重复；旧版的「最近三次」列 —— 移入趋势页。

## 四、打印规格

- `@page { size: A4; margin: 9mm }`；正文字号 9.5–10.5px，行高 1.45；
- 趋势段强制新页（`.trends { page-break-before: always }`），保证「指标在前、图在后」；
- 打印按钮 `position: fixed` + `@media print { display:none }`（打印时不留痕迹）；
- 卡片 HTML **自包含**：无外部 CSS/JS/字体/图片，折线图为内联 SVG —— 另存为 `.html` 后离线也能打印；
- 实测（2026-11-13）：4 项指标 + 1 条趋势 → 2 页（第 2 页仅趋势）；105 行量级仍为 1 页正文 + 1 页趋势。

## 六、验收判据（可复跑）

```bash
node tests/verify-card.mjs     # 19 条：版式、行数完备性、异常倒序、趋势截断、脱敏 fixture
node tests/verify-intake.mjs   # 解析层 23 条（单栏 20/23、双栏 26/26、单位规范化、推定标记）
```

必须成立的不变量（少一条就是静默丢数据）：

1. `counts.rows` == 输入行总数；**卡面上每个项目名都出现**（不是「看起来一页装下」）；
2. 「全部指标」段渲染行数 ≥ `counts.latest`，且 ≠ 分组数（防「一组一行」复活）；
3. 异常项日期序列 == 逆序排列；
4. 卡面不得出现「最新指标」段（2026-11-13 口径）；
5. 打印：A4 页数 ≤ 2（正文 1 页 + 趋势 1 页）在 105 行量级下。

## 七、留给下一位 AI 的开放问题

1. 异常项要不要**按临床重要性**二次排序（粒缺/血小板 <20/发热优先于 LDH 轻度升高），还是严格按时间？当前按时间。
2. 趋势图画几条合适？当前最多 8 条；医生实际更关心 MRD 与血常规 3 项。
3. 「原件」按钮的位置：挂在卡面每一行（回溯到来源图）还是卡片末尾的「材料清单」？当前计划是后者。
4. 病理/骨穿这类**自由文本**报告的卡片结构（摘要段落 + 关键结论原句）尚无规格。
5. 是否需要在卡面标注每项指标的**数据来源报告**（日期 + 医院），以便医生质疑时定位。
