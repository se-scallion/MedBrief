# 问诊资料卡 · 逻辑规格 v3（可直接交给 AI 改）

> 读者：**门诊医生**（血液科）。使用者：**患者 / 家属 / 代诊人**。
> 介质：**A4 PDF（打印 & 微信传阅为主）+ 自包含 HTML（手机/电脑浏览器，可点原件）**。
> 目标：把跨院、跨时间的多份检查单，变成 **第 1 页 1 分钟看懂病情 + 第 2 页全量可查不漏项 + 第 3 页趋势变化**。
>
> 版本：v3（2026-11-13，基于 54 份真实报告压测 + 双向排雷后定稿）。
> v2 → v3 的实质变化：数据地基（字段清洗 + code 覆盖）→ 1+1+1 分页 → P0/P1 分层 → 最新状态口径 → 危急值 → 时效提醒 → 原件按钮。

## 零、先读这一节（血的教训，改之前必看）

1. **真实数据里有 9 行「三列整体左移」**：`名称(含着真值) | 值=参考区间 | 参考区间=单位`。
   例：`{"name":"凝血酶原时间（P12.2个T）","value":"9.8-12.1","refRange":"sec"}` 的真义是 `PT=12.2，参考 9.8-12.1，单位 sec`。
   后果：卡面「值」显示的是参考区间、参考区间显示的是单位；且 `sec` 不是区间 → 无法判高低 → `status=unknown` →
   **既不进异常项、也不报错**。修复在 `lib/labClean.mjs` 的 `repairColumnShift()`，读侧生效，不改真实数据。
2. **code 覆盖率曾经只有 6/204**（且全部来自病理 FCM 适配器）——原因是新导入工作流那条路径根本没写 `code`。
   现在读侧统一用 `classifyAnalyte()` 补（覆盖率 203/204 = 99.5%），`ANALYTE_CATALOG` 仍是**唯一登记处**。
3. **模糊匹配会串码**：`红细胞平均血红蛋白含量`(MCH) 含 `血红蛋白` 会冒充 Hb；`有核红细胞占有核细胞比例` 会冒充 RBC。
   所以 `classifyAnalyte` 的「包含匹配」只在调用方显式传 `{ loose: true }`（仅对已标 `nameDirty` 的脏名）时启用。
4. **不要拿 `data/reports.json` 当断言靶子**：那是活数据（3 小时内 49→54 份）。断言一律对
   `tests/fixtures/card-snapshot-v3.json`（脱敏冻结快照，`tools/make-card-snapshot.mjs` 生成）。

## 二、处理规则（改任何一条必须同步改 `tests/verify-card.mjs`）

1. **读侧清洗（`lib/labClean.mjs`，幂等）**：列左移还原 → 单位/区间串位纠正 → value 尾巴噪声 → 名称清洗（剥数值/箭头字/定性结果/圈号）。
   约束：干净行零改动；固有编号（`CO2`/`pCO2`/`CD34+`/`白介素6`/`P190型`）**不得**剥。
2. **code 优先归并**：有 `code` 用 `code`，无则退回 `name`。`code` 是去重 / 趋势聚类 / 危急值判定的唯一键。
3. **判定高低**：① 先认报告自带箭头/定性 → ② 再按参考区间比 → ③ 区间非法（`high < low`）置空不猜。
   颜色：高=红 `↑`、低=绿 `↓`。
4. **最新状态口径**：每个 `code` 只判**最近一次**是否异常（历史波动交给趋势页）。
   **不做**「近 14 天曾危急」提示（真实数据近 14 天 0 份报告，无法验证；真做需先在 `cardPolicy` 加窗口函数并有单测）。
5. **P0 / P1 分层**（`lib/cardPolicy.mjs` 的 `P0_CODES`）：
   - **P0 展开**：血常规全组、凝血、肝肾功电解质、炎症（CRP/PCT/IL-6）、骨髓/流式/MRD/遗传、铁代谢、血气乳酸，
     **以及尿潜血 / 尿白细胞 / 尿红细胞（永远 P0，不按报告类型一刀切）**；
   - **P1 折叠**：其余（尿胆原/酮体/尿糖/比重/镜检其他、血气偏差、血型/血清学/病原、粪便）。
   - 折叠形式：一行摘要「另有 N 项非核心异常（组名…），见第 2 页」。
6. **排序**：危急值优先 → `measuredAt` 新→旧。
7. **危急值**（`CRITICAL_RULES`，阈值可配）：`WBC<1.0 或 >50`、`ANC<0.5`、`Hb<60`、`PLT<20`、`FIB<1.0`、`Lac>4.0`、`K+<2.8 或 >6.0`。
   命中 → **置顶 + 浅红底纹 + 「危急」微标**（避免极低值只标绿造成安全错觉），并强制升入 P0。
8. **全部指标（第 2 页）**：按 `code` 去重取最新，按医生阅读顺序分组，**100% 不漏项**。
9. **趋势（第 3 页）**：同 `code` 且单位归一后一致、出现 ≥2 次才画；优先 MRD/骨髓原始/WBC/ANC/Hb/PLT/CRP/LDH/铁蛋白，最多 8 条。
   - **跨院参考区间不一致** → 不画单一绿带，改 `⚠️ 跨院参考区间不同` + 列出各院区间；
   - **单位确实无法统一** → 不硬拼，进「未绘制（单位不一致）」说明。
10. **缺项**：`REQUIRED_BASICS`（WBC/Hb/PLT/**ANC**/PT/APTT/FIB/LDH）缺失时，卡面显式写「未提供：…」。
    「没查」与「没给我」临床含义不同，必须让医生看见。
11. **时效提醒**：最近一次**有指标**的报告超过 `STALE_DAYS=90` 天 → 第 1 页「核心异常项」标题下方琥珀色警示：
    `⚠️ 最近一次有指标的化验为 YYYY-MM-DD（距今 N 天…），请注意时效性`。数据新鲜时不得误报。
12. **材料清单**：`rows` 为空的报告标 **「—」= 未结构化（仅存原件）**，并在表下用图例说明，
    **绝不许写「0 项」**（会被读成解析失败丢数据）。`text-only` 标「无原件」。
13. **冲突与留痕**：`valueConflict` 数值后加 `*`；`nameDirty` 项目名后加 `?`；页脚各一行说明。
14. **红线**：只陈述数值、日期、判定、趋势与出处；**绝不写诊断结论、治疗建议或预后判断**。

## 四、验收判据（`tests/verify-card.mjs` 29 条 + `tests/verify-labclean.mjs` 14 条）

| # | 判据 | 为什么 |
|---|---|---|
| 1 | `counts.rows` == 输入行总数；每个项目名都出现在卡上 | 防「按组渲染」静默丢数据（历史事故：105 行只剩 6 行） |
| 2 | 第 2 页渲染行数 == `counts.latest` 且 ≠ `counts.groups` | 防退化成「一组一行」 |
| 3 | 第 1 页行数 == `counts.p0`，且同项不重复出现 | 最新状态口径（3 份历史 × 3 项 → 只留 3 行） |
| 4 | P1 项不出现在第 1 页表格、只出现在摘要行 | 分层不是为了好看，是为了不淹关键项 |
| 5 | 危急值有 `class="crit"` + 「危急」且排在首行 | 极低值不能只有绿标 |
| 6 | `missingBasics` 含 ANC 时卡面出现「未提供：」 | 粒缺不能靠百分比猜 |
| 7 | 超 90 天 → 出现时效警示且含具体日期；新鲜数据不误报 | 防止把 100 天前的数当本周的 |
| 8 | 0 行报告 → 「未结构化（仅存原件）」且**无「0 项」** | 防止被读成解析失败 |
| 9 | 有原件 → 按钮指向 `/api/intake/blob/<id>`；text-only → 「无原件」 | 可回查 |
| 10 | `trends ≤ 8`、`trendsAll` == 可比较总数、关键项必须留 | 截断不许丢关键项 |
| 11 | 跨院 `refRange` 不同 → 有警示且**无 `<rect>`** | 不画虚假精度绿带 |
| 12 | 单位不一致 → 进「未绘制」并说明 | 宁缺不错 |
| 13 | 红线词库零命中 | 合规 |
| 14 | 三段分页 CSS 存在；手机 media query 存在 | 打印/手机两条消费路径 |
| 15 | 清洗层：幂等 / 干净行零改动 / 列左移还原逐值核对 / 固有编号不剥 / 串码防护 / code 覆盖率 ≥99% | 数据地基 |

## 六、留给下一位 AI 的开放问题

1. 第 2 页**材料清单会随导入增长**（54 份已占 446px）：超过约 60 份必然溢到第 4 页。
   要选：按年月折叠 / 允许第 2 页自然分页（总页数变 4）/ 材料清单移到应用内而非 PDF。
2. **`value` 里仍夹中文标记**（`3.27上`、`22.00小`）—— 已清洗，但 `35（++）` 这类定性值的 `num` 解析仍可能被误当数值参与危急值判定。
3. **血气与生化同名不同轴**（血气 `Hct` vs 血常规 `HCT`）已分 code，但**趋势图上仍可能出现两条相似曲线**，需在图上标「血气」来源。
4. `nameInferred`（序号插值补全的名称）目前只在数据里标记，卡面没显示 —— 要不要在第 2 页加轻量 `?`（与 `nameDirty` 共用一个标记）。
5. 危急值阈值全部硬编码在 `lib/cardPolicy.mjs`，是否要开放成 `patient.json` 里的可配置项（不同医院血库阈值不同）。
