# 报告导入 · 固定流程（SOP）

> **口径已统一**：本文件的流程已并入 `docs/导入工作流.md`（唯一入口，含判重四层与原件 Blob）。两者冲突时以该文件为准。

> 把「一批病友报告」变成「可回查的结构化记录 + 一页给医生的 A4 卡」的**唯一通路**。
> 首次定稿 2026-11-12（样本：`V00000000000` 血液肿瘤免疫分型报告单，某实验室甲/乙版式）；同日加批量与并发。
> 版本语义：**流程固定，版式可长**。新增报告形式 = 新增一个适配器文件，本流程与 CLI 不动。

## 一、六步流程（每一步都有可复跑命令）

| # | 步骤 | 实现 | 不可省的理由 |
|---|---|---|---|
| 1 | **取数** | `tools/pdf-extract.py`（PDF 文本层，按 y 聚类重建行）／`POST /api/intake/ocr`（图片，含 deskew→crop→chunk→Vision）／直接读 `.txt` | PDF 文本层的 raw 顺序是**绘制顺序**，不重建行就配不上「标签：值」 |
| 2 | **选适配器** | `tools/report-adapters/index.mjs` 的 `pickAdapter(text)`：按版式特征打分，`lab-panel` 兜底 | 版式差异必须收在适配器里，不能写进主流程 |
| 3 | **结构化** | 适配器 `parse({ text })` → `{ meta, rows, warnings }`；结论类报告可返回 `textOnly: true` + `rows: []`（全文进 `report.text`） | 只照抄原文（红线见 §四）；`parseLabRows` 的可信度闸门不许版式表头冒充指标 |
| 4 | **查重** | `POST /api/intake/reports` 内：sha256（精确）／dHash ≤6/64（近重复）／内容指纹（0 行报告额外按 `reportType+barcode` 区分）；dHash 由 `tools/dhash.py` 对**同一张图**算出 | 宁可重复不可丢；命中只提示，不静默删 |
| 5 | **人核对** | 默认 dry-run 打印核对表（每行带 `rawSnippet` 原文片段）、可疑行与「未写库」提示；`--review suspect` 只列可疑行 | OCR/解析不可能 100%，核对是流程的一部分 |
| 6 | **入库 + 出卡** | `--apply` → 写 `data/reports.json`（写库前守卫：0 行且非 `textOnly` 拒绝）；`GET /api/intake/card` → `data/intake/card.html` + `card.json` | 卡片只陈述数值/日期/出处 |

```bash
# 单份（默认 dry-run，只打印核对表，收尾会明确说「未写库」）
node tools/import-report.mjs report.pdf

# 单份真入库（诊断/分型这类字段只有显式传参才写，绝不猜）
node tools/import-report.mjs report.pdf --apply --update-patient \
  --diagnosis "急性B淋巴细胞白血病（Common-B-ALL可能）" \
  --subtype "流式免疫表型推断（2026-07-17）；送检临床诊断原文「AL?」"

# 结论/病理类报告：karyotype 等 textOnly 适配器只转录抬头 + 全文回查，0 指标行是合法结果
node tools/import-report.mjs karyotype.pdf --apply
```

退出码：`0` 全部处理完（含查重跳过）｜`2` 单文件模式查重命中｜`3` 有文件无适配器/解析 0 行｜`4` 有文件失败。
**例外**：`textOnly: true` 的全文型报告 `rows: []` 不算「解析 0 行失败」（见 §四 红线 6）。

## 二、批量与速度（几十份报告的正确用法）

```bash
# 一个目录一次跑完：并发 4（默认），只把可疑行端给你看
node tools/import-report.mjs --dir ~/Desktop/报告待导入 --apply --review suspect

# 混着来也行：多文件 + 目录可以同时给
node tools/import-report.mjs a.pdf b.png --dir ./more --concurrency 6 --apply
```

| 参数 | 作用 | 建议 |
|---|---|---|
| `--concurrency n` | 同时跑几份（1–8，超出夹到 8） | 默认 4；纯图片批量可到 6–8，长尾延迟会涨（见下表） |
| `--review all\|suspect\|none` | 核对粒度 | 新样本首份用 `all` 通读一遍；同版式后续用 `suspect`（默认：单文件 all / 多文件 suspect） |
| `--dir <目录>` | 目录里所有 `pdf/png/jpg/jpeg/webp/tiff/txt` | 一次性把手机导出的整个文件夹丢进来 |
| `--force` | 查重命中仍入库 | 只在人确认「确实不是同一份」时用 |

**实测（2026-11-12，本机 8008 macOS Vision；8 份 = 6 张 1240×760 截图 + 2 张超高图）**

| 方式 | 总耗时 | 每份平均 |
|---|---|---|
| 串行（`--concurrency 1`） | 5788 ms | 724 ms |
| 并发 4 | **2008 ms** | 251 ms |
| 并发 8 | **1693 ms** | 212 ms |

**8008 并发标定**（同一批图，单请求延迟 vs 吞吐）：并发 1 → 594 ms/份；4 → 183 ms/份；8 → 154 ms/份；12 → 143 ms/份（单份延迟涨到 1.7 s，所以默认取 4，不取 12）。

**超高图切块**：h/w 3.06（1240×3800）切 2 块，块间**并行**后 1.83 s → 1.09–1.29 s（`server.mjs` 的 `/api/intake/ocr` 已改 `Promise.all`）。

**带文本层的 PDF**：OCR 耗时 0（直接读文本层，解析 <50 ms）——所以**优先要 PDF 原件**，比截图快一个数量级。

> 结论：批量慢的根源是「串行 + 每份一轮人回话」，不是解析。并发 + `--review suspect` 两者叠加，
> 50 份图片从「一份一份问」变成「一两分钟跑完 + 只挑可疑行给你看」。

## 三、新增一种报告版式（三步，不改主流程）

1. 新建 `tools/report-adapters/<form>.mjs`，默认导出：

```js
export default {
  id: 'xxx',                                  // 唯一 id，出现在核对表与 --json 输出里
  title: '人读的名字',
  match(text) { return /版式特征/.test(text) ? 1 : 0 },   // 0 = 不认领；越具体越靠前
  parse({ text }) {
    return { meta: { kind, reportType, reportDate, hospital, patientName, ... }, rows: [...], warnings: [...] }
  },
}
```

2. 在 `tools/report-adapters/index.mjs` 的 `ADAPTERS` 登记（顺序 = 优先级，`lab-panel` 必须最后）。
   **共用函数放 `tools/report-adapters/shared.mjs`（叶子模块）**，不要从 `index.mjs` 反向 import —— 会形成环（实测报 TDZ）。
3. 在 `tests/verify-import-report.mjs` 加只读断言：该版式的**已脱敏文本**（`tests/fixtures/`）断言行数、逐项值、红线。

> 脱敏硬要求：fixture 里不许出现真实姓名 / 病案号 / 条码 / 床号 / 医生 / 院名 / 院址 / 电话。
> 生成方式：`python3 tools/pdf-extract.py <真实pdf>` 取 lines → 字符串替换 → `grep` 复核残留。

## 四、红线（改流程前先读，任何适配器都不得违反）

1. **不编造临床事实**：报告写「异常细胞占有核细胞比例 85.76%」就存这个名，**不许**改写成「骨髓原始细胞 85.76%」或「MRD 85.76%」；读不到就不产出该行。
2. **不编参考区间、不判高低**：流式/病理报告没有参考区间 → `refRange: ''`、`status: 'unknown'`，卡片「判定」列显示 `—`。
3. **每行留证**：`rawSnippet` 必填（`parseLabRows` 与各适配器都要带），报告全文进 `report.text`。
4. **身份字段不落库**：身份证 / 手机号 / 住址一律不收。
5. **不静默丢**：查重、切块残值（`valueConflict`）、名称推定（`nameInferred`）、可信度闸门丢掉的版式文字行，都要留痕并进入 `--review suspect` 列表。
6. **解析 0 行 = 失败**：退出码 3，绝不把空表当「导入成功」。**唯一例外**是 `textOnly: true` 的全文型报告（结论/病理类）：`rows: []` 是设计结果，全文必须进 `report.text`，适配器要在 warnings 写明「自由文本不字段化」，CLI 与服务端都按此放行；其它版式不得借这个口子写空表。

## 六、实测记录

### 2026-11-12 第一份真实样本（流式免疫分型）

```
取数   PDF 文本层（4 页，未做 OCR、未走视觉模型）
适配器 flow-immunophenotype
抬头   姓名/性别/年龄/标本/医院/科别/医生/条码/采样/接检/报告日期/主检实验室 全部命中
指标行 6 条：异常细胞 85.76 / CD34+ 84.42 / 粒细胞 9.27 / 有核红细胞 2.51 / 淋巴细胞 2.19 / 单核 0.27
入库   rep_mwdo3ous9k7（kind=pathology, reportType=FLOW_CYTOMETRY, reportDate=2026-07-17）
查重   同一份 PDF 重投 → {dup:true, kind:'exact'}（退出码 2）
门禁   verify-import-report 15/15；verify-intake 23/23；verify-card 18/18；verify-unit 23/23；
       verify-chunker 17/17；verify-deskew 10/10
```

### 踩过的坑（都已在代码里用注释钉住）

1. **PDF 文本层是绘制顺序**：抬头 8 个标签先出、5 个值后出，逐行正则配不上对 → 必须按 y 聚类成行。
2. **MuPDF 的语法错误写 fd 1**（`cannot find ExtGState resource`），只重定向 `sys.stdout` 拦不住 → 调用 fitz 期间把 fd 1 指到 devnull，否则 CLI 的 JSON 被污染。
3. **页脚陷阱**：注释里有「自报告日期起的三天内提出复检申请」，只搜「报告日期」会先命中它 → 判据必须「报告日期 + 日期」连写。
4. **水印**：真实单据每行叠「姓名首字 + 条码」→ 跨行重复 + 形态判定，只删独立成词的位置。
5. **`classifyAnalyte` 的双向 `includes` 会串码**：`有核红细胞占有核细胞比例` 命中键 `红细胞`→`RBC` → 流式项目必须逐条登记原文名到 `ANALYTE_CATALOG`。
6. **裸词「医院」抓错值**：`某医院检验科` 会把「检验科」当院名 → 医院必须「带冒号的明确标签」才认。
7. **适配器 ↔ 注册表循环 import**：从叶子文件直接 import 时报 `Cannot access 'labPanel' before initialization` → 共用函数下沉到 `shared.mjs`。

### 2026-11-12 第二份真实样本（染色体核型分析报告单，停在人核对，**未写库**）

**输入**：微信 drag 目录单个 PDF（1.28 MB，1 页，有文本层，60 词 / 24 行），与上一份流式报告**同病人、同条码、同送检实验室**，但版式是「染色体核型分析报告单」。下文记作 `$PDF`，姓名/院名/条码不落记录。

**过程**

| # | 动作 | 结果 |
|---|---|---|
| 1 | 服务体检：`curl 5174 /api/intake/reports`、`curl 8008 /api/agent-mode`、`lsof -iTCP:5174` | 均 200；5174 由 node 常驻监听 |
| 2 | `node tools/import-report.mjs "$PDF"`（用户给出的原命令） | **默认 DRY-RUN 不写库**；227 ms（复跑 `--json` 145 ms）；`status=parsed`、适配器 `lab-panel`、**1 行**、退出码 0 |
| 3 | `python3 tools/pdf-extract.py "$PDF"` 复核文本层 | 1 页 24 行；抬头为「标签(EN)：值」双栏表单；正文是核型公式 + 结果描述/解释 + 检测结论；**全篇没有「报告日期」字段**，只有采集/接检时间 |
| 4 | 核对表 | 抬头只命中性别「女」，姓名/医院/报告日期全空；唯一「指标行」= `检测结果(ISCN` / 值 `2024`（原文 `检测结果(ISCN 2024) 检测结论`） |
| 5 | `--review` 可疑行 | 只有「姓名未读到 / 报告日期未读到」，**那条假指标没被标可疑** |
| 6 | `npm run test:import` | 15/15 通过 —— 现有断言不覆盖「非化验版式被兜底解析出假行」 |
| 7 | 离线模拟 `--apply` 的查重三道 | 渲染 `page-1.png` 的 sha256 与库内不同；dHash 汉明距离 **16/64**（阈值 ≤6）；内容指纹不同 → **三道都不命中**，真跑 `--apply` 会写入一条 `kind=lab / reportDate='' / 1 行假指标` 的记录并改写资料卡 |

按 §一 第 5 步「人核对」结论：这份不该入库，故**未执行 `--apply`**；`data/reports.json` 仍是 1 份 / 6 行。期间未改任何代码。

**问题**

1. **兜底把版式表头当指标（最严重）**：`检测结果(ISCN 2024)` 里的 `2024` 是 ISCN 版本号，`parseLabRows` 的名称正则允许括号（且不校验闭合）、值取行内第一个数字 → 造出一行假指标。比「解析 0 行」更危险：0 行会退出码 3 拦住入库，**1 行假行是退出码 0**，`--apply` 会静默写库。
2. **兜底不认中英双语标签**：`姓名(Name)：` / `就诊医院(Hospital)：` / `采集时间(...)：` 让 `lab-panel` 的 `grab()` 与日期正则全部失配；`flow-immunophenotype` 已有 `LABEL_RE` / `splitLabeledLine` 能吃这种标签，但能力没有共享。
3. **日期口径不一致**：核型报告无「报告日期」，只有采集/接检时间。流式适配器有「采样日期兜底 + warnings 留痕」，兜底适配器没有 → 日期空 → 入库后 `rows.measuredAt` 也空 → 资料卡趋势段丢行。
4. **可疑行判据漏掉假行**：`collectSuspects` 只看 `valueConflict / nameInferred / num 非数 / 缺 rawSnippet / 抬头缺失`；`2024` 是纯数值且有原文片段 → 不报。缺少「这一行看起来不像化验指标」的判据（无单位、无参考区间、名称括号未闭合、值像年份、整份只有 1 行）。
5. **无 `KARYOTYPE` 适配器 + 红线 6 冲突**：核型公式跨 3 行、结论是自由文本（按 §七 边界 1 不字段化）。但「解析 0 行 = 失败，退出码 3」意味着「只做抬头 + 全文回查」的适配器反而**不让入库**；且服务端 `/api/intake/reports` 在 `rows` 为空时会回退 `parseLabRows(text)`，把假行又塞回来。属于流程对「结论类报告」的语义缺口，需先拍板口径。
6. **命令语义误导**：脚本叫 `import-report`，默认却只打印计划；用户按「导入」给的命令实际没写库，且退出码 0 + `parsed` 很容易读成「导入成功」。本次是真实发生的误读。
7. 次要（本次未触发）：同批不同报告只被查重「区分」，没有按条码/就诊**正向关联**；`archive()` 渲染第一页失败被 `catch` 吞掉时 `body.image` 仍为 null → sha256/dhash 全空，只剩内容指纹查重。

**已验证不是问题**：PDF 文本层可直读（无需 OCR，取数 <250 ms）；y 聚类后「标签：值」成对正确；同批不同版式**没有**被近重复查重误杀（16/64 > 6）；门禁 15/15 无回归。

**优化点（同日用户拍板「优化吧」后已落地，见下一小节）**

| 优先级 | 优化点 | 落点 |
|---|---|---|
| P0 | 兜底「可信度闸门」：指标行至少要有 值 +（单位/参考区间/箭头/定性词）之一，年份型整数 + 未闭合括号名直接丢；非化验版式宁可 0 行退出码 3 也不许 1 行假行；把本次样本做成门禁断言 | `parseLabRows` / `lab-panel` / `collectSuspects` / `verify-import-report` |
| P0 | `--apply` 前守卫：无可信指标行或 suspect 含「疑似非化验版式」时拒绝写库；结束时明确打印「未写库，确认后加 `--apply`」 | `import-report.mjs` |
| P1 | 「标签(EN)：值」解析下沉 `shared.mjs`，流式与兜底共用同一套抬头字段（含采集/接检时间）；无报告日期时按采样时间兜底并留痕 | `shared.mjs` / 两个适配器 |

## 六、原件入库（Blob）与「AI 核对结果」入库（2026-11-13 新增）

### 6.1 为什么原件必须进库

用户口径：**入库必须带原件**，以后系统升级换识别模型时能拿原件重新识别，不依赖当时的 OCR 结果。

- 存法照 MedData 的 `blobs` 表：`data/medbrief.db`（**node:sqlite 内置，零新增依赖**），表 `blobs(id, sha256, kind, type, size, width, height, origin_path, report_id, created_at, data BLOB)` + `blob_tombstones`。id 前缀 `f_`，与 MedData 的 docFileStore 同约定，便于将来互通。
- 报告记录新增 `sourceBlobs: [{blobId, role, sha256}]`；`role` = `original`（原图/原件）或 `stitched`（跨屏拼接图）。
- 接口：`POST /api/intake/blob`（dataUrl/base64 → blobId）、`GET /api/intake/blob/<id>`（取回字节）、`GET /api/intake/blobs`（清单 + 存储统计）。
- 兼容：原件同时复制到 `data/intake/<patient>/archive/<sha8>/`，沿用旧 CLI 的归档目录约定。

### 6.2 批量入库用 `tools/import-inbox.mjs`（不是 import-report.mjs）

```bash
node tools/import-inbox.mjs --manifest data/tmp/inbox/manifest.json          # dry-run
node tools/import-inbox.mjs --manifest data/tmp/inbox/manifest.json --apply  # 真入库
```

manifest 里带 **已人工/AI 核对过的 rows**（不是让项目重新解析），每份：先存原件 blob → 再 POST /api/intake/reports。

### 6.3 两个已证实的项目缺陷（绕开，别回退）

1. **`parseLabRows` 丢定性行**：`ABO血型鉴定=B型`（4 行）、粪便常规 `粪便外观/脂肪球/夏雷登氏晶体/霉菌/虫卵`（5 行）因「值不是数字」被整行丢弃 → 用 `tools/ocr-table-rows.mjs` 的 `parseOcrTable()`：按 `检验项目/结果/参考范围/单位` 四列逐行收，定性值原样留，`rawSnippet` 必带。
2. **dHash 近重复判据在文本截图上失效**：`凝血 07-26` 与 `凝血 08-04` 汉明距离 = **0**，14 张不同影像报告会被聚成一簇。已给 `findDuplicate()` 加护栏：dHash 命中必须同时「单号相同或报告日期相同」，否则不算重复（两个都没传才退回旧行为）。

### 6.4 跨屏配对的可复跑判据

无抬头页（第 2 屏）用「**页1 尾部 k 行 == 页2 头部 k 行（名称+数值都要相等）**」匹配，不靠文本相似度（同版式不同日期的血常规文字几乎一样，相似度会误配）。

| 单号 | 类型 | 证据 |
|---|---|---|
| 20260701G0000001 | 血常规 | 重叠「嗜酸性粒细胞百分比 = 0.6」 |
| 20260701G0000002 | 血常规 | 重叠 3 行（单核 0.5 / 中性 15.8 / 嗜酸 0.34） |
| 20260701G0000003 | 生化 | 重叠「二氧化碳(CO2) = 25」 |

**拼接图不能当数据源**：拼接后整图重跑 OCR 会丢行（实测 `20260701G0000003` 丢 2 行、`20260701G0000002` 丢 2 行）。所以 rows 用两页各自 OCR 的行并集（去重叠），拼接图只作完整原件归档。
