# 字段字典（报告导入 → 存储 → 将来同步 MedData）

> 回答三个问题：**存在哪、字段叫什么、哪些是这次新建的**。
> 最后核对：2026-11-12（第一批流式样本入库后）。改动本文件 = 改契约，必须同时改 `docs/报告导入流程.md` 与 `INTERFACE.md`。

---

## 一、存储形态（先说清楚，避免误解）

| 问题 | 事实 |
|---|---|
| 是「数据库」吗？ | **不是数据库，是 JSON 文件**：`data/reports.json`（`{version:1, reports:[…]}`，已被 `.gitignore` 覆盖）+ `data/intake/patient.json`。项目里没有 SQLite/Postgres。 |
| 为什么不用库 | 单机、单用户、几十份报告的量级；JSON 可 diff、可手改、可回滚，且没有并发写需求 |
| 表结构变更怎么办 | 当前**只做字段追加**（旧记录缺字段 → 读时按空串/`null` 处理，不写迁移脚本也不破坏既有记录）。真要改语义（删改字段名/换结构）时按 D5 走：`data/reports.json` 加 `version` 迁移脚本，可前进可回退 |
| 和 MedData 的关系 | **MedBrief 不写 MedData 任何库**（8787 是只读权威）。此处字段口径**对齐** MedData 的 `records[] / data_points[] / diseaseMetrics[]`，目的是将来导出/同步时不用二次翻译 |

## 四、code 命名空间（这是「要不要建新字段」的答案）

规则：**能复用 MedData 已有的就不新建；字典外的走 `custom:<slug>`；只有「新的检测维度指标」才申请新的标准 code。**

| 项目（报告原文名） | code | 类型 | 说明 |
|---|---|---|---|
| 异常细胞占有核细胞比例 | `FCM_MRD_PCT` | **复用 MedData 已有** | MedData `STREAMS.fcm.code`，定义即「异常表型细胞/有核细胞 %」，同一测量轴。诊断时点 85.76% 与后续 MRD 值共用一条趋势，不另建平行字段 |
| CD34+细胞占有核细胞比例 | `FCM_CD34_PCT` | **新建标准 code** | CD34+ 是独立于 MRD 总百分比的标志（可单独随访），故单列 |
| 粒细胞占有核细胞比例 | `custom:fcm-gran-pct` | **新建自定义字段** | CD45/SSC 门内各群比例，属描述性事实，不进标准字典 |
| 淋巴细胞占有核细胞比例 | `custom:fcm-lymph-pct` | **新建自定义字段** | 同上 |
| 单核细胞占有核细胞比例 | `custom:fcm-mono-pct` | **新建自定义字段** | 同上 |
| 有核红细胞占有核细胞比例 | `custom:fcm-nrbc-pct` | **新建自定义字段** | 同上 |

### 这批字段在 MedData 侧需要做的事（不做也不影响 MedBrief 出卡）

1. `FCM_CD34_PCT`：若要进 MedData 的「病情三维度·流式」与 `/api/summary`，需在 MedData 字典登记（`SUMMARY_DISEASE_CODES` 等）——**改动在 MedData 仓，不在本仓**；
2. 4 个 `custom:fcm-*-pct`：按 MedData 既有约定落进 `store.customFields`（`{code, name, unit, ref, addedAt}`），符合 `CUSTOM_CODE_RE = /^custom:[a-z0-9][a-z0-9_-]{0,63}$/`；
3. 同步前**只需**这三类字段（`standard_code` / `original_name` / `value+unit` + 日期）即可，其余是显示与回查用。

> 反向约束：`ANALYTE_CATALOG`（`lib/reportIntake.mjs`）是 MedBrief 侧项目名→code 的**唯一登记处**。新增流式项目必须逐条登记原文名，
> 否则 `classifyAnalyte` 的双向 `includes` 会把 `有核红细胞占有核细胞比例` 串到 `红细胞`→`RBC`（实测：2.51% 会冒充「红细胞 2.51%」）。

## 五、自检

```bash
node tests/verify-import-report.mjs   # 24 断言：字段口径、红线、dry-run 不写库、闸门/全文型/指纹
node tests/verify-intake.mjs          # 23 断言：解析/分组/查重（含 code 归类）
```

问：「新加了哪些字段？」→ 第一批：报告级 7 个（`reportType/labName/barcode/sampledAt/receivedAt/clinicalDiagnosis/sourceFile`），
行级 5 个（`originalName/stream/analyte/qualifier/rawSnippet`），code 侧 1 个新标准码（`FCM_CD34_PCT`）+ 4 个自定义字段 + 1 个复用（`FCM_MRD_PCT`）。
第二批（核型全文型报告）：**没有新增存储字段**，只新增 `reportType` 取值 `KARYOTYPE` 与「`rows: []` 合法」的形态；
`meta.textOnly` 只存在于入库请求体，用来跳过服务端空 rows 回退解析，不落库。
