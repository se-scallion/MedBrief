# 前端依赖（已知约束，不是待办）

> 一句话：**MedBrief 的前端依赖是「借」MedData 的 `node_modules`，不是自己装的。**
> 这条以前是隐性的（新环境 `vite build` 直接炸），2026-11-13 显式写下来。

## 事实

| 项 | 现状 |
|---|---|
| 根 `node_modules` | 符号链接 → `../MedData/node_modules` |
| `web/vite.config.js` | `resolve.modules` 显式指向 `../node_modules` |
| 根 `package.json` | `dependencies` 只有 `playwright`；前端 7 个包写在 `medbriefFrontendDeps`（非标准字段，**npm 不会安装**，仅作声明与版本锁定） |
| `meddata/` | 自己没有 `package.json`，同样依赖上面那棵树 |

## 锁定的版本（与 MedData 当前树一致）

```
react 19.3.0   react-dom 19.3.0   antd 6.6.6   dayjs 1.11.23
pdfjs-dist 4.10.38   react-router-dom 6.30.6
vite 8.3.4   @vitejs/plugin-react 6.1.2
```

## 换机器 / 换目录怎么办

1. 把 MedData 仓放在与本仓同级的目录（`../MedData`），或把它的 `node_modules` 软链到本仓根；
2. 确认上面 8 个包版本一致（`node -e "console.log(require('antd/package.json').version)"`）；
3. `npx vite build --config web/vite.config.js` 能过 = 环境就绪。

## 为什么不直接自己装

`antd 6.x + react 19` 是一套很新的版本矩阵，MedBrief 的组件（以及 `meddata/src` 里搬来的识别组件）
都是对着这棵树写的。独立声明一份依赖树等于引入第二次版本漂移，**改依赖属「会影响构建的变更」**，
要走 PM 上报，不在日常重构范围内。

## 已知后果（可接受）

- `npm ci` 在本仓没有意义（前端包不在 `dependencies` 里）；
- 跨仓耦合：MedData 升版本会连带影响 MedBrief 前端构建。
