## 访问 114yygh.com 的两个硬条件（2026-11-12 实测，缺一不可）

- **UA 必须含 `MicroMessenger`**。缺它 → 瑞数 WAF 直接返回 **462**（`content-length: 0`、`server: unicom`、`x-cache: BYPASS`），
  业务代码根本没被执行。实测：Chrome UA 下 9/10 请求 462；换微信 UA 后全 200。
- **渠道必须走 `pathchannel=jt`（京通，渠道 value 16）**。用 `pathchannel=dp`（点评/大众点评，value 32）
  → 业务层返回 `{"code":"8888","message":"点评用户授权失败，请退出北京114预约挂号页面重新进入"}`。
  两条件齐备时：14 个请求全 `code 0000`，首页「共 309 家医院」正常渲染。`wechat` 渠道会跳授权页，不可直连。

## 微信对象 WeixinJSBridge 与 114 的关系（2026-11-14 实测，ego lite 只读首页）

- **实测范围（别当全局结论）**：只测了「未登录、只读首页」——不注入时 `typeof window.WeixinJSBridge === 'undefined'`，
  首页仍渲染「共 309 家医院」、页面无报错。**登录后的查号/选号/下单链路没跑过**，
  因此只能说「首页不依赖它」，不能说「挂号不需要它」。已有的两条硬门槛（UA 含 `MicroMessenger` + 真实指纹）
  另有独立证据，与 bridge 无关；bridge 是否为第三条必要条件**仍未验证**。
- **注入会被页面感知**：桥存在时页面立刻 `invoke("setFontSizeCallback", {fontSize:0})` 并 `on("menu:setfont")`（无害）。
- **全站唯一业务级 bridge 调用是医保**：`invoke("invokeMiniProgramAPI", {name:"openMedicalInsuranceService",
  arg:{appId,path,envVersion,extraData}})`；另一条降级路径走页面自带 jweixin 1.6.0 的 `wx.miniProgram.navigateTo`
  （`/jingtong/jt_package/ep_public/pages/yb_pay/index?...`）。注入只能截出参数，真正拉起医保小程序必须由微信客户端完成。
- `wx.config` 的 appId/timestamp/nonceStr/signature 由站点服务端按 `location.href` 下发，**伪造无效**，别在这上面花时间。
- 驱动层入口：`egoRun(script, { wxBridge: true })` 与 `egoProbeWxBridge()`；注入必须在 `page.goto` 之前，
  且与 UA 覆盖同一纪律——**只对本次连接的新文档生效**，每个动作都要重新置位。

## 不要用 curl / requests 直连接口

瑞数的 `HKNCYzbu` 令牌由页面 JS 动态生成，且与 TLS/UA 环境绑定。实测拿浏览器真 cookie（含 HttpOnly）回放，
经 Clash 与绕过 Clash **都仍是 462** —— 这条路走不通，必须用真实浏览器内核（ego lite / Playwright 实体 Chromium）。

## 登录链路（已跑通到短信发出）

手机号 → **图形验证码**（`GET /captcha`，先过这步才发短信）→ 短信（`POST /phoneCode`，返回 `data.time=60` 冷却）
→ 提交验证码完成登录。图形码是 4 位数字，可从页面 `<img>` 的 blob 取出识别。

## 根本需求（用户 2026-11-12 定稿，高于一切功能）

> 「导入病友的病例、报告单，获得问诊（医生视角的）病况资料，用于给门诊医生快速了解病人情况。」

- **数据只来自用户导入的文件**：不读 MedData 的 `/api/summary`、`/api/state` 等任何库。MedData 只能当 OCR 引擎用（8008），不是数据源。
- **挂号是次要功能**：主鸿鹄在 114 **没有号（用户确认，不是待确认）**，不做常驻扫描、不默认自动轮询；用户点了才查一次。
- **页面结构按功能权重**，不是「一级页 ≤ 3」：高频且直接产出交付物的（导入 → 校正 → 资料卡）放前台一页做完；低频工具进抽屉且默认不跑。
- 交付物 = **问诊资料卡**（一页 A4，可直接打印给医生），设计见 `docs/问诊资料卡.md`。
- 红线不变：只陈述数值/时间/趋势/出处，不写诊断结论与治疗建议；缺项必须显式声明（区分「没查」与「没给」）。

## 资料卡版面口径（2026-11-14 用户拍板）

- **趋势卡不画底部「文字点位行」**（`07-27 3.27 · 07-18 71.90 …`）：它只是把折线上的点再念一遍，
  没有独立信息量；精确数值在第 1 页「最新值」与第 2 页「全部指标」里都有。**删掉，不再加回**
  （守卫断言：`tests/verify-card.mjs`「趋势格只留折线：不得再出现底部文字点位行」）。
- **功能开工前先去 MedData 找现成实现**：先抄它的 bug 结论，再抄代码、组件、模块；前端一律用 antd
  现成组件，不手写列表容器。落地细节见 `.agents/architecture.md`「MedData 的位置 / 铁律」。

## 资料卡版面口径（2026-11-14 19:20 用户第二轮微调）

- **趋势图必须能读数**：每张图必须有 **Y 轴刻度**（3 档，取真实值域）和 **每个点的数值标注**；
  数值/日期一律与 X 轴同序（左旧右新）。「图上看不出量级」和「图上图下相反」都算缺陷。
- **初诊流式 ≠ MRD**：`异常细胞占有核细胞比例` 在最早那次流式里写 **`初诊异常细胞 85.76%`**；
  只有名称明确带「MRD/微小残留/残留病」或**比最早那次更晚**的复查，才标 `MRD`。
- **参考区间装的是注意事项文本 → 显示 `—`**（原文本留 `refRangeNote` 供回查）：
  如 Rh(D) 的 `*Rh血型阴性、阳性均为正常…`，它与左列「阳性」并排会被读成自相矛盾。
- **第 2 页「其他感染筛查」折叠**：ABO 正定型/反定型/鉴定/酶法鉴定 → 1 行「ABO血型」+ Rh 1 行（共 2 行）；
  乙肝/丙肝/HIV/梅毒 **永远单列**，任何阳性结果也永远单列；其余全阴性的常规病毒/抗体按主题折成
  `呼吸道病原筛查 6项（07-17）：均阴性`。判据：**折叠前后项数必须守恒**，组内有阳性则整组逐项列出。
- **解释文本行不进卡面**：OCR 把参考说明（`<300pg/ml-非急性心衰`、按年龄分层阈值）切成结果列时，
  该行标 `noteRow` 剔除（清空必须留 `note-dropped` 标记，不许静默）；真值一律回原文核对补正
  （本次 NT-proBNP 实测值 **3182.00 pg/ml**，`<300` 是说明不是结果）。

## 报告删除（2026-11-14 用户拍板，覆盖旧「不提供删除」）

- 报告**要能删**，但必须是**可恢复的软删除**：删除 → 进回收站（指标从资料卡消失、原件字节保留）→
  可恢复；只有「彻底删除」（且仅当报告已在回收站里）才动原件字节，且要二次确认写明不可恢复。
- **资料卡页不加删除入口**（我给的单一口径）：资料卡是给医生看的纸质材料，误点风险高于收益；
  删除集中在报告库。家属说明书里「不提供删除报告」那段必须随功能上线同步改写。
