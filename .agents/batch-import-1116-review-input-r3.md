## 本轮必攻击点（4 条）

1. **B4 是否真的能分辨**：我写的量测点是 `scrollTop = (scrollHeight - clientHeight) * 0.5`。若 ① 段总高不足两屏（例如只有 2 张卡），`maxScroll*0.5` 仍可能落在"栏自然位置已在视口内或刚好贴底"的区间 ⇒ 该判据是否仍能红？要不要再补一个"内容必然 ≥3 屏"的夹具前提？
2. **`MAX_SELECT = 4` 与 `MAX_STITCH = 2` 并存**时，用户选 3 张会看到「拼接」禁用 —— 是否需要在栏上给一句解释文案（如「拼接：需选 2 张」）而不是只靠 `title`（手机无 hover）？
3. **B5（改前基线）**：我按你的方法用 5194 + 副本库量 `?tab=intake`。若改前就超宽，我打算把该判据降级为"改后 ≤ 改前"，并在交付说明里明确写"横滚未修"。这个处置够不够？
4. **P0-1 的降级态计数**：我加了「疑似重复（粗判）N」；但降级态下"卡内灰 Tag（本次未做文件查重）"与"橙 Tag（可能重复·粗判）"会同时出现在同一张卡上（一张说"没查"，一张说"可能重复"）。这是否自相矛盾？要不要合并成一条文案（如「未做精确查重；按文件名+大小疑似重复，请核对」）？
