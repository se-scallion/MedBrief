## A. 反向排雷（现有现实 → 新方案的前提）

- **R1｜「按钮太多/太占地方」的现场成立，且位置比用户说的更糟。**
  证据：`web/src/pages/intake/UploadPanel.jsx:56-64` —— 「已勾选 N/2（用于拼接）／拼接选中的两张／清空勾选」这一整行排在**卡片列表之前**；N 张卡片用 `Row gutter` 铺在下面（`:67-131`）。报告一多，用户必须先滚回顶部才能点拼接 —— 用户原话「再跑到页面上方点击拼接」与代码一致。
- **R1b｜「每卡都有识别按钮」成立，且是**两层**重复。**
  证据：`UploadPanel.jsx:125-127` 每卡一个 `block` 按钮（占满整行宽）；`:29-33` 顶部还有一个「一键识别全部（N）」。同一件事两个入口，正是用户说「简化」的对象。
- **R2｜「删」与「选」确实是文字按钮。** 证据：`UploadPanel.jsx:104-110`，`删` 是 `type="text" danger` 的两个汉字，`选/已选` 是普通 `size="small"` 按钮。
- **R3｜「重复提示要前移到导入时」—— 现在做不到即时，因为查重**只在入库那一步**发生。**
  证据链：`dupCount` 只统计 `status === 'dup'`（`web/src/pages/IntakePage.jsx:573`）；而 `status='dup'` 只由 `recognize()` 拿到后端 `body.duplicate` 时设置（`:447-453`）；后端查重唯一调用点是 `POST /api/intake/reports` 内的 `findDuplicate`（`server.mjs:1683`）。
  ⇒ 现状态：**导入 → 什么都不知道 → 识别 → 也可能不知道（识别不查重）→ 入库才被拦**。用户要的「刚导入就提示」目前**没有任何检测点**。
- **R4｜「刚导入就能查重」只能诚实覆盖一种情况：同一文件字节已导入过。**
  `findDuplicate` 的判重口径（`lib/reportIntake.mjs:83-130`）：① `sha256` 完全相同 → `kind:'exact'`；② 单据级 `条码+报告日期+报告类型` 三者相同（`:95-101`）；③ 文本 2-gram Jaccard ≥0.9（`:105`）；④ dHash ≤6 且 `sameDoc`（`:113-130`）。
  导入那一刻**只有文件字节**，没有条码/日期/类型/文本 ⇒ 能用的只有 ①。
  **而 ④ 不能前移**：`lib/reportIntake.mjs:115` 的实测注释写着「『凝血 07-26』与『凝血 08-04』汉明距离 = **0**，14 张不同影像报告会被聚成一簇」—— dHash 预检会把**不同日期、同版式**的报告误报成重复。前移 ④ 等于重新引入这个已被咬过的坑。
  ⇒ R4 结论：**导入即提示 = 「这个文件你已经导入过了」（exact sha256）**，文案必须写清是"同一个文件"，不许写"疑似重复报告"（否则用户会以为系统认得单据）。
- **R5｜现有列表接口已经能支撑 R4，不必加端点。**
  `GET /api/intake/reports` 用 `...r` 展开整条记录、只把 `text`/`images` 置 `undefined`（`server.mjs:1005-1010`）⇒ **`sha256` 已在返回体里**。前端 `loadReports()` 已把这份清单存在 state（`IntakePage.jsx:164-172`）。⇒ 预检 = 客户端算文件 sha256 + 与这份清单对表，**零后端改动**。
- **R6｜前端现在**没有**文件指纹。** `addFiles()` 只建 `{...dataUrl:''}` 与 `_file`（`IntakePage.jsx:153-183`），`sha256` 全靠入库时后端算（`server.mjs:1667`）。⇒ 要接 R4 必须前端新增一次哈希计算。
- **R7｜「拼接」的 2 张上限是**纯前端**限制，后端本来就收 N 张。**
  证据：`/api/intake/stitch` 只要求 `images` 非空（`server.mjs:1384-1392`），`stitchVertically(dataUrls, {gap,bg})` 本身吃数组（`lib/reportIntake.mjs:141`）；限制写在前端：`toggleSelect` 超 2 就挤掉最早的（`IntakePage.jsx:214-221`）、`doStitch` 校验 `selected.length !== 2` 直接 return（`:222-231`）。
- **R8｜「一键导入」和「一键识别」现在被拆在**两个面板**里，用户根本看不见它们的关系。**
  证据：「一键识别全部」在 ① 面板（`UploadPanel.jsx:29-33`），「一键导入」在 ② 校对面板顶部（`IntakePage.jsx:905` 的 `onImportAll`）。⇒ 用户说的「一键识别导入」，实际是**两步两个地方**。这解释了为什么他会问"合并还是拆开"。
- **R9｜「隐藏无关按钮」不是纯美问题：当前 375px 下每张卡 24 列全宽（`Col xs={24}`），一张卡约占一屏 1/3。**
  证据：`UploadPanel.jsx:68`（`xs={24} sm={12} md={8}`）。卡片里纵向堆了 缩略图(120px)+大小/行数+整行"识别"按钮 ⇒ 4 张卡要滚 3 屏以上。用户要求"简洁"的实质是**一屏能看见更多张**。
- **R10｜「刚导入就查重」在手机端可能**算不了哈希**（待实测）。**
  `crypto.subtle` 只在安全上下文（`https:` 或 `localhost`）可用。手机经局域网 `http://192.168.x.x:5174` 打开时 `window.isSecureContext === false` ⇒ 没有 `crypto.subtle.digest`。
  **`[未取证]`**：需要真机或 Playwright 以非 localhost 源验证。若成立，降级方案见 D 段前提问题 4（**绝不假装查过**）。

## B. 正向排雷（新方案 → 现有消费方）

- **F1｜`selected` 现在是"拼接专用"的 2 元素数组，改成通用多选会打穿 3 处。**
  `toggleSelect`（`IntakePage.jsx:214-221`）靠"超 2 就挤掉最早的"实现拼接上限；`doStitch`（`:222-231`）用 `selected.length !== 2` 当闸；UI 上还有「已勾选 N/2（用于拼接）」（`UploadPanel.jsx:57`）。
  ⇒ 若 `selected` 变成通用多选（1…N），必须同时改：① `toggleSelect` 不再截断；② `doStitch` 改 `>=2` 并保序（拼接顺序 = 勾选顺序）；③ 文案去掉 `/2`。
  **顺序语义是新雷**：现在的 2 张拼接隐含"先选的在上面"，多选后必须有明确的"拼接顺序"（建议按勾选顺序，UI 显示 `① ②` 序号），否则拼出来的上下顺序随机。
- **F2｜`removeItem` 是内存删除，不是库删除 —— 文案必须区分，否则会被当成"删库里的报告"。**
  `removeItem` 只 `setItems(filter)`（`IntakePage.jsx:208-212`），删掉的是**还没入库的本次导入条目**；库内删除是另一条已立项的线（`intake-dedupe-1116`：②批量软删 / ④PC 常显 / ⑤移动端隐藏）。⇒ 固定栏的「删除」文案必须写「移除选中（未入库）」，且**不要**做成红色 danger 到让人以为是删库（建议 secondary + 二次确认只在 ≥3 张时）。
- **F3｜新增"文件级重复"状态不能复用 `status:'dup'`，否则会污染三处统计与一键导入的跳过逻辑。**
  `status==='dup'` 被消费于：`dupCount` 标签（`UploadPanel.jsx:21`）、`recognize()` 的分支（`IntakePage.jsx:447-453`，还会 `pushLog` 并 `return {duplicate:true}`）、`importAll` 的 `c.dup` 计数与"已跳过"文案（`:506-523`）。
  ⇒ 预检结果必须落**独立字段**（如 `predup: {kind:'exact-file', of}`），卡片上单独一个 Tag；`status` 不动。否则「我来得及在导入时发现的重复」与「入库时被后端拦下的重复」会被揉成一个数，用户看不出差别。
- **F4｜固定栏会与 ① 顶部分段条 / ② 校对区的保存行打架。**
  页面有吸顶分段条（`IntakePage.jsx:104-140`，`scrollMarginTop: 56`）；② 校对区末尾有保存行（`mb-review-grid` 保存按钮，`IntakePage.jsx:732` 注释）。固定栏常驻会盖住最后一行内容 ⇒ 必须给内容区补 `padding-bottom: 栏高 + 安全区`，并在 ② 段落时**隐藏或降级**固定栏（否则用户永远点不到"保存到本地数据库"）。
- **F5｜测试污染。** 所有验证走副本库 + 5193–5199 端口（沿用 `tests/verify-reports-refresh.mjs` 的做法）；不许碰 5174/真库。
- **F6｜调用面：本次不改 `server.mjs`。** 预检靠既有 `GET /api/intake/reports`（R5）；多张拼接靠既有 `/api/intake/stitch`（R7）。⇒ 只需重建 `dist-next`，不需要重启后端（F7 也就只是"重建产物"）。
- **F7｜部署态。** `web/**` 改完必须 `MEDBRIEF_WEB_BASE=/ MEDBRIEF_WEB_OUT=dist-next npm run build:web` + 浏览器硬刷新；由我执行并自验产物哈希。
- **F8｜治理资产对齐。** 若采纳 R4 的"文件级预检"口径，`docs/导入工作流.md` 的判重口径段要同步补一条「预检只判 exact 字节重复，不做 dHash 预判」，否则下个会话会把预检当单据级查重。
- **F9｜并发写。** 本次只动 `web/src/pages/intake/UploadPanel.jsx`、`web/src/pages/IntakePage.jsx`、（可能）`web/src/pages/intake/shared.js`。当前 `git status` 里这三个文件**未被他人改动**（在途的只有 `.agents/outsourcing-log.md`、`.agents/testing-lessons.md`、`lib/reportStore.mjs`）⇒ 可认领。开工前再核一次。

## D. 简化后的方案 + 延后触发条件 + 我无法自解的前提问题

### D-1 留下的七条（MVP）

1. **卡片头部改成三位一体**：`Checkbox`（左上/右上）+ 状态 Tag + 文件名（`ellipsis`，保留 tooltip）+ `DeleteOutlined` 图标按钮（右上角，`aria-label="移除此文件"`，`title` 同文）。宽度不够时文件名先截断，不做换行。
2. **撤掉每卡的整行「识别」按钮**；仅当 `status === 'done'` 出「重新识别」（`ReloadOutlined` 小图标按钮）、`status === 'failed'` 出「重试」。
3. **下方浮动固定操作区**（移动端与大屏都常驻，位置 `fixed; bottom`，宽度随容器；内容区补 `padding-bottom`）：
   - 未选中：`一键识别（N）` + `一键导入（M）` + 「更多」
   - 选中 1 份：`移除选中`（+ 回到上面的两个主操作，但弱化为 text）
   - 选中 ≥2 份：`拼接选中（N）`（按勾选顺序，卡片上显示 `①②③`）+ `移除选中`
   - 批量进行中：`识别中 3/7` + `停止`（沿用现有 `batch` 状态）
4. **多选语义统一**：`selected` 变为通用多选；`doStitch` 改 `>=2` 且上限 4；拼接顺序 = 勾选顺序。
