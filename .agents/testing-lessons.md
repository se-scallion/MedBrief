# 测试与排查教训 — MedBrief / 114 挂号

## 2026-11-12 · 462 与 8888 是两层，混为一谈就查不出根因

- **462 = 瑞数 WAF 在传输/UA 层拒了**，业务代码没执行。判据：`content-length: 0` + `server: unicom` + 响应体为空。
- **8888 = 业务层鉴权不足**，HTTP 是 200、回包是真 JSON：`{"code":"8888","message":"点评用户授权失败…"}`。
- **正确顺序**：先看 HTTP 状态（462 ⇒ UA/环境问题）→ 再看 body 的 `code`（8888 ⇒ 渠道/授权问题）→ 最后才疑接口参数。
- 代价：早期把 462 当成「接口参数不对」，反复改 header 无效，浪费多轮。

## 2026-11-12 · 「绕开代理就好了」的误判：对比必须控制变量

- **错误姿势**：用无 cookie 的裸 curl 绕开 Clash 得到 `202`，就判定「Clash 的 TUN 栈导致 462」，并提出改 `tun.stack`。
- **反例**：用浏览器真 cookie（含 HttpOnly）分别经 Clash / 绕 Clash 打同一请求，**四种组合全 462**。
  202 只是「新客户端应得的挑战页」，与代理无关。
- **判据**：任何 A/B 对比必须锁死除被测变量外的全部条件（同一 cookie、同一 body、同一 UA）。
  条件不对等的对比，结论必须显式标注不可用。

## 2026-11-12 · 自动化点击的三个坑（都真踩过）

1. **`page.fill()` 不触发 Vue 更新**：input 的 DOM `value` 变了、页面显示也对，但 Vue model 仍为空 →
   按钮一直是 `again-button-disabled`，点了也不发请求。**必须** `mouse.click` 聚焦后用 `keyboard.type()` 真实输入。
2. **坐标落在视口外**：按钮 `getBoundingClientRect().y = 1120`，而视口高 1087 → 点击等于点空白，
   表现为「点了没反应、无请求、无报错」。**必须先 `scrollIntoView({block:'center'})` 再取坐标**。
3. **移动端可能绑 touch 而非 click**：页面 UA 是 iPhone 时，`click` 未必触发；用
   `CDP Input.dispatchTouchEvent`（touchStart → touchEnd）更可靠。

## 2026-11-12 · ego-browser 的 UA 覆盖不跨进程

`Network.setUserAgentOverride` 只对当前 CDP 会话有效，进程退出即失效。
**多步流程（填号→识别图形码→提交）必须在同一次 `ego-browser nodejs` 调用内完成**，
否则下一次调用页面已掉回默认 UA，请求重新 462。同理 `Page.addScriptToEvaluateOnNewDocument`
注入的钩子也可能丢失，关键动作前重新注入。

## 2026-11-12 · 图形验证码的处理姿势

点「获取验证码」不是直接发短信，而是先 `GET /captcha` 下发 4 位图形码。
取图要从页面里的 `<img>`：`data:` URL 直接取 base64；`blob:` URL 需在页面内 `fetch` 后转 base64 落盘再识别。
识别结果是**一次性**的，须在同一会话内立即填入提交，超时需重新拉取。

## 2026-11-12 · 判断「服务不可用」前，先看轻量接口

排查 114 时曾把「请求挂死 40–150s」误判为站点故障/配额。
**正确做法**：先用不消耗资源的接口（`GET /v2/models`、`countTokens`、静态资源）验证 key/网络是否正常，
再判断重接口失败是配额、限流还是环境问题。轻量通 + 重接口挂 = 额度或环境，不是 key 失效。

## 2026-11-12 · 想在页面里挂 XHR 钩子：必须用 addScriptToEvaluateOnNewDocument

- **踩了两次同一个坑**：用 `page.evaluate(() => { 替换 XMLHttpRequest.prototype })` 装钩子，
  然后 `page.goto(...)` —— 钩子随旧文档一起销毁，新页面里一行都抓不到（表现为 `keys: []`、`calendarStatus: null`）。
- **正解**：`page.cdp("Page.addScriptToEvaluateOnNewDocument", { source })`，钩子在每次新文档创建前注入，跨导航存活。
- **判据**：抓到「什么都没拦截」时，先怀疑钩子装晚了/装错层，再怀疑接口没被调用。
  同一个 URL，换注入方式后立刻抓到 21KB 的 `hospital/list`（309 家）。

## 2026-11-12 · 参考区间 `126--350` 被负数正则误解析 → 假「偏高」（真实数据当场抓到）

- **症状**：`parseRefRange('126--350')` 返回 `{low:126, high:-350}`，导致血小板 238 被标红为「高」、WBC 4.02 标「高」。
  根因：正则 `(-?\d+)` 允许上限带负号，`126--350` 就吃成 `126` + `-350`。库里 20 条化验区间有 2 条是这种 OCR 双连字符。
- **修法**：先把 `– — ~ 〜` 归一成 `-`、`-{2,}` 折叠成单个 `-`，再解析；并校验 `high >= low`，不合法返回 null。
- **判据**：任何"从报告文本里取数值/区间"的解析，必须拿**库里的真实脏数据**跑一遍；合成数据永远造不出 `126--350`。
  固化：`tests/verify-unit.mjs` 的「速览：OCR 双连字符参考区间不得误判」断言。

## 2026-11-12 · 「一页装下」最容易变成「静默丢数据」：渲染断言行数必须等于数据行数

- **现象**：资料卡渲染层按「指标分组」循环，每组取 `g.rows[0]` 渲染一行 → 105 项指标只出 6 个 `<tr>`，
  看着像「一页就装下了」，实际丢了 99 项，而且**没有任何报错**。
- **判据**：任何「汇总/压缩展示」的渲染，都必须有一条断言：**渲染出的数据行数 == 源数据行数**（或明确声明的截断数）。
  只断言「页面不报错」「HTML 有内容」是抓不到这类 bug 的。
- **代价**：这一天里同类错误出现两次（另一处是删掉别人写了 419 行但未被引用的组件）。
  共同点都是「我用一个隐含假设（未引用所以可删 / 一页所以压行）替代了核对」。
- **做法**：压测用**最坏情况数据**（3 份报告 × 35 项 = 105 行），并量出真实页数（playwright `page.pdf()` 数 `/Type /Page`），
  不靠肉眼估。资料卡 105 行从「3 页 → 1 页」是靠「最新值两栏 + 趋势只留 8 项」达成的，不是靠少渲染。

## 2026-11-12 · 「渲染行数 == 数据行数」这条判据在压缩式版式下要改写

- 我上一版写的判据是「card.html 数据行数 == 105」，但四段式资料卡里 ② 只放 35 项最新值、③ 只留 8 条趋势，
  **105 个数据点本来就不会各占一行**——按字面写出来的断言必然要么错、要么逼着人把卡撑回三页。
- 正确判据（代诊-报告改的，采纳）：判**信息有没有丢**，不判**行数相等**：
  ① `counts.rows == 105`（入口处一个不丢）；② **35 个项目名在卡上全部出现**；③「最新指标」段实际渲染行数
  ≥ `counts.latest` 且 **≠ `counts.groups`**（专门守「一组一行」复活）；④ 段标题写的项数 == `counts.trends`
  （防标题谎报）；⑤ 一页上限用实测阈值（`<tr> ≤ 80`、`HTML ≤ 24KB`）。
- **方法论**：断言要贴着「用户实际会损失什么」写，而不是贴着某个实现细节写；实现一改版式，错判据会先红，
  然后被人当成噪音关掉——那比没有断言更糟。

## 2026-11-12 · 图像切块/拼接：重叠必须 ≥ 一行文字高，否则边界行两块都残

- 切超高图做 OCR 时，重叠 60px 实测 24+23 = **47**（少 1 行）；90/120/160px 都稳定 24+24 = 48。
  该单据一行字高约 86px —— **重叠小于一行高，边界行在分块 A 里被切掉下半、在分块 B 里被切掉上半，
  两边都认不出**；重叠 ≥ 一行高时必有一块完整。
- **判据**：块间重叠 = max(30px, 一行字高 × 1.2)，并写断言「相邻块重叠 ≥ 一行高」。
- 配套坑：块边界切残的行会产出**错值**（实测「血小板 45」→ 边界块出「血小板 10」）。
  因此块合并**不能按「值相同」去重**（错值会被当成新行留下），要按 **(码, 日期) 内值投票**、冲突标 `valueConflict`。
  这是「同一条记录在两次观测里出现不同值」的通用形态：**合并键要选「稳定标识」，不要选「观测值」**。

## 2026-11-12 · 手机拍照的「倾斜 2°」是识别率杀手，缩放/灰度反而不致命

用合成化验单（11 项）做四组失真实测（同一张图，只改一个变量）：

| 失真 | 解析行数 | 结论 |
|---|---|---|
| 原图 | 11/11 | 基线 |
| **旋转 1°** | 11/11 | 无影响 |
| **旋转 2°** | **8/11** | **掉 27%** |
| 旋转 3° / 5° | 9/11 | 掉约 18% |
| 缩到 800px 宽（微信压缩） | 11/11 | 无影响 |
| 灰度 + 低对比（contrast 0.55） | 11/11 | 无影响 |
| **旋转 2° 后反向回正** | **11/11** | **完全恢复** |

- **判据**：真正需要预处理的是**倾斜（deskew）**，不是清晰度/分辨率。
  行带聚类（`groupBlocksIntoRows`）依赖「同一行 y 接近」，倾斜后同一行跨 y，聚类直接崩 → 行数腰斩。
- **修法**：OCR 前做 deskew（对角 ±5° 搜索 + 水平投影方差最大），实测回正后 100% 恢复；
  或按 Vision 返回的块坐标估计斜率再反向旋转。
- **教训**：我先猜「分辨率/清晰度」是瓶颈，实测两者都无影响。**先做单变量实验，再决定优化谁。**

## 2026-11-12 · 预处理链会互相污染：deskew 撑大的白边让「超高切块」判据失效

- 现象：歪 2° 且 h/w 2.92 的重图，deskew 回正后画布旋转补白边 → 宽度 2223 → 2448，
  **h/w 掉到 2.68**，跌破切块阈值 2.8 → 不切块 → 中间带照旧丢行（48 行只剩 43）。
- **判据**：后处理步骤若改变了几何尺寸（旋转/补边/缩放），它之后的**所有尺寸类阈值都必须重算，
  或者先归一到「内容 bbox」再算**。实测：回正后裁掉白边 → 1864×6295、h/w 3.38 → 切 2 块 → 48/48 恢复。
- **顺序不能乱**：正确链条是 `deskew → 裁内容 bbox → 按 h/w 判切块 → 逐块 OCR`；
  反过来「先切块后 deskew」会把每行撕成斜口，比不切更糟。
- **泛化**：凡是「多个预处理/判定步骤串联」，都要问一句「上一步有没有悄悄改掉下一步依赖的量」。
  这次的变量是宽度，下次可能是 DPI、坐标系原点、单位。

## 2026-11-14 · 先量「不注入会怎样」：微信对象不是通行证

- 现象：为「让页面以为自己在微信里」去注入 `WeixinJSBridge`。实测（ego lite，未登录只读 114 首页）：
  **不注入时 `typeof window.WeixinJSBridge === 'undefined'`，首页照样渲染「共 309 家医院」，页面无报错。**
  → 能下的结论只有「首页/目录渲染不依赖它」；**登录后的查号/下单链路未实测**，不要外推。
  （这正是本条要教的东西：对照实验的能量只覆盖你实际跑过的那条路径，超出的部分是猜测。）
- **判据**：任何「补一个环境对象让它以为自己在 X 里」的方案，动手前先跑一次**不补的对照**；
  没有对照就分不清「页面需要它」和「页面碰巧容忍它」。
- 注入生效的判据不是「对象存在」，而是**页面真的开始用它**：注入后页面立刻
  `invoke("setFontSizeCallback",{fontSize:0})` 并注册 `menu:setfont` —— 这才叫「页面认了」。
- 工程纪律：CDP `Page.addScriptToEvaluateOnNewDocument` 必须在 `page.goto` **之前**注册；
  且与 UA 覆盖同理，**只对本次连接打开的文档生效**，每个动作都要重新置位。
- **自审抓到的坑**：页面自带的 `jweixin` 是异步 `<script>`，在 `DOMContentLoaded` 之后才赋值 ——
  只挂 `DOMContentLoaded` 会漏包 `wx.miniProgram`（"包上了"是错觉）。**hook 第三方异步对象要挂三个时机**
  （`DOMContentLoaded` / `load` / `setTimeout 0`），并用 `miniProgram.__wrapped === true` 实测确认。

## 2026-11-14 · 断言贴着数据结构，就抓不到「用户看到的是相反的」

- 现象（用户报障）：趋势卡折线左旧右新（07-14 → 07-27），底下那行字却是 07-27 → 07-14。

  数据侧断言 `points` 升序，渲染侧就必须断言 `html` 里那段文字与 `points` 同序。
  本次的出口是直接删掉那行字 + 一条「不得再出现 `class="tpts"`」的守卫。
- **自查顺序**：先 `grep` 渲染产物（`card.html`）里用户会读到的字符串，再看数据结构对不对。
