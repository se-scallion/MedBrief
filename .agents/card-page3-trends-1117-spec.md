## 3. 标签密度规则（现状即合同，逐条写死）

实现见 `lib/intakeCard.js:879-918`，本规格把它固化成"不许随意改"的合同：

1. **点一个不少**：折线上每个时间点都画（`dots` 全量）。
2. **数值标签必标 4 个**：**首点 / 末点 / 最大值 / 最小值**（临床最常读）。
3. **其余数值标签贪心补标**：仅当它与「上一个已标标签」的横向净距 ≥ **2 viewBox 单位**时标；估算宽度 `labelW = 字符数 × 4.2 + 3`。
4. **必标点彼此太近**（`< 26` 单位）时：`dy` 按 **三档 `[-14, 9.4, -22]`** 轮换错行，不许改成"少标"或"换行显示"。
5. **日期标签两级避让**：最小间距 `< 26` 单位 ⇒ 奇偶两行错位（画布高度 +8）；仍 `< 13` 单位 ⇒ 抽稀到「首点 / 末点 / 每月首点」。
6. **禁止事项（本次事故的根）**：**不许**用"标签会叠"当理由去改 ① 列数 ② `viewBox` 宽度 ③ 点数。要改必须走 §4 或找我出 v2。

## 4. 唯一待定（需要我出 v2 才能动，实现方不许自己动）

`viewBox` 宽 300 与实际内宽 345.8 不一致 ⇒ 文字恒定被放大 1.153×。两个选项：
- **(A) 保持现状**（推荐）：字号 ≈8.07px 可读，改动收益小、风险是全部标签重排。
- **(B) 把 `w` 传 346**：字号回到 7px（更小、更密），但几何 1:1、跨页一致性更好。

**结论：取 A，不改。** 若将来用户嫌字小，走 B 属于"字号契约变更"，必须我先出 v2 规格并给实测对比。
