## 本轮必攻击点（逐条回答）

1. **P0-1 的"批内命中不新增第二张卡"与"对库命中仍建卡"是我拍的**：这样会让"批内误选"静默少一张、而"隔天重导"仍能看到卡。请判断这个**不对称**是否合理，还是应该统一（两边都建卡并打 Tag）。
2. **P0-2 选 (d) 纯 JS SHA-256**：40 行实现进入 `web/src` 意味着一份**自写密码学**代码。请判断：① 是否该只对 `>2MB` 的文件才用纯 JS（大文件循环慢）？② 是否需要"只算前 1MB + size"的折中（会削弱 exact 语义，我倾向不做）；③ 这条要不要单独一行"不许引入第三方依赖"的硬约束。
3. **D-4 第 5 条"改前也跑一次作 must-be-0 基线"**：现状 ① 段在 375 下是否已经存在横滚？如果改前就 >`innerWidth`，这条断言会"改前红、改后绿"被误当成收益。是否需要先量一次？若需要，给出不碰真库/5174 的量法。
4. **C-9 挂起后，D-1 第 4 条"上限 4"是否自相矛盾**（挂起就意味着本轮仍只允许 2 张）。请指出该怎样措辞才不误导实现方。
5. **新增断言 D-4 第 8/9 条**（批内/对库重复）需要造两个夹具（同一 File 选两次、库里已有 sha256 的图）。请判断这两个夹具能否用 5194 + 副本库做出，还是需要 `MEDBRIEF_DATA_DIR` 另造 blobs。
6. **F4 的"② 段整条隐藏"**：`sec` 由 `IntersectionObserver` 的 `intersectionRatio` 最大值决定（`IntakePage.jsx:126-140`），页面在 ①→② 之间滚动时可能反复切换 ⇒ 固定栏会**闪**。请判断这是可接受（UI 可加过渡）还是必须先改判定逻辑（如 `sec==='upload'` 之外再加"距顶部 > X"）。
7. **v0.2 是否还有 r1 §4 表里标 ⚠️/❌ 而未在本版落地的项**（我用「修订说明」表逐条对过，但你是独立复核方）。若有，点名编号即可。
8. **UI 规格未回**：本版所有尺寸写"待 UI 定"。请判断 r2 判「可以开工」是否必须以数值规格到位为前提；若是，我把它写成 r3 的前置条件，而不是先开工再补。
