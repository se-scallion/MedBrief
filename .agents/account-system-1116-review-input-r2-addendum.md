# r2 补充约束（用户拍板 Q1 · addendum）

> 用户在 r2 审核进行中回答了此前卡住的第一个待拍板问题，原文：
> **「管理员账号是我13228372097。这些报告归属另外一个1320000000。」**
>
> 这是对 r1/r2 判词中 D4-Q1 的用户补充约束，按 plan-review §8.2 规定写成 addendum，须在下一轮明确交审。
> **本轮审核者请在 r2 判词里直接回应本 addendum 的三条影响**（若已完成 r2 判词，则在 r3 首轮处理）。

## 1. 用户决定改写了什么（与 v0.2 推荐值相反）

| 项 | v0.2 推荐值（被推翻） | 用户实际决定 |
|---|---|---|
| 本地管理员账号 | `13200000000` | **`13228372097`**（与 114 平台实名号**同号**） |
| 报告归属账号 | 与管理员同一个 | **另一个账号**，用户写作 `1320000000` |

**设计影响**：
- 必须是**至少两个本地账号**：`admin(phone='13228372097')` + 报告所有者 `user(phone=?)`。
- 管理员 ≠ 报告所有者，所以"管理员天然看全部报告"要显式定义：admin 是否绕过 `report_owners` 过滤？计划 D1 现有措辞是"只返回本人 owner 的报告"，对 admin 没写例外——需补。
- **号码位数歧义（必须澄清）**：用户本次写 `1320000000` 是 **10 位**；原始需求写 `13200000000` 是 **11 位**（中国大陆手机号应 11 位）。**暂按 11 位 `13200000000` 处理并标 `[待用户确认位数]`**，不得静默选一个。
- `users.phone` 与 114 号同号但**体系不同**：114 登录态 = `cmi-user-ticket`（`server.mjs:817`），本地 = `mb_session`，互不认证。r1 §3-1 的"允许相同也不许复用登录态"约束**从建议升级为必须**。

## 2. 请审核者判的三条

1. **两个账号的建号顺序与授权语义**：bootstrap 应建 admin + owner 两账号；owner 是否自动获得 `card_export`/`guahao` 授权，还是默认全是普通用户（只看报告库）由管理员后续授权？计划没有写，是否构成新 P0？
2. **admin 的 owner 过滤例外**：D1 表 `:154` 写"登录即可 → 只返回本人 owner 的报告"，但管理员不是报告所有者——若照字面实现，管理员建好后**看不到任何报告**，也就无法验证/授权。这是不是一个必须修的 P0？
3. **位数歧义的处理**：`[待用户确认位数]` 标记是否足以让实现者不停工？还是必须先问用户拿到 11 位确认才能开工（即新增 G6 阻塞项）？
