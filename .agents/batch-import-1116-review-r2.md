## 2. v0.2 新增的问题：2 条 P0 + 5 条 P1

### P0-1 降级路径的 `name+size` 命中，会**静默少一张卡**（可能真丢）

D-1 5.5 写：「哈希完全不可用时，**批内**用 `name+size` 相同判『疑似误选两次』」；而 5.3 写：「**批内**命中 ⇒ 不新增第二张卡，`message.warning` + `pushLog`」。两条连起来就是：

> 手机端（哈希不可用，见 R10）用户选了两张**同名同大小**的不同截图（手机相册/聊天软件常见 `image.jpg`、同分辨率截图字节数相同）⇒ **第二张直接被丢弃，只剩一条提示**。

这与项目红线「不静默丢数据」正面冲突，且**降级态恰恰是手机端（主场）**。

**必改**：
1. 5.5 命中后**只打 Tag，不跳过**（`predup.kind:'name-size-suspect'`，文案「可能重复（按文件名+大小粗判，请核对）」）。
2. 5.3 的「不新增第二张卡」**只适用于 `crypto` 可用时的 exact sha256 命中**，并在文字里写死这一前置条件，别让实现方以为降级也跳过。
3. 降级态顶部必须有可见计数（「本次跳过 0 / 疑似重复 N」），否则用户永远不知道该核对什么。

### P0-2 `doStitch` 改 `>= 2` 等于**事实放行了挂起的 C-9**

D-1 #4 原文：「`selected` 改通用多选，**上限 4**；…`doStitch` 改 `>=2`（C-9 挂起前，前端仍按 2 张启用，多张开关一并挂）」。

这三句互相打架：上限 4 + `doStitch >= 2` ⇒ 用户选 3 张 → 按钮可点 → **真的拼 3 张**（`/api/intake/stitch` 收 N 张，`server.mjs:1387-1392`）⇒ C-9 已被实现，而它正被挂起、且**服务端无尺寸/数量护栏**（`stitchVertically`，`lib/reportIntake.mjs:144-161`），手机端 3–4 张 4000px 图有 OOM/超时风险。

**必改**（措辞与实现都要）：
1. 写成一个常量：`const MAX_SELECT = 2`（C-9 未放行前），`toggleSelect` 按它截断，`doStitch` 判 **`selected.length === MAX_SELECT`**（不是 `>= 2`）。
2. D-1 #4 删掉「上限 4」与「`①②③` 序号」两句，改成「结构按 1..N 通用设计，本轮 `MAX_SELECT = 2`；C-9 放行时只改常量 + 打开序号显示」。
3. D-2 的 C-9 放行条件里补一句：**放行时必须同时给 `stitchVertically` 加数量上限（建议 ≤4）**，因为 `server.mjs` 无护栏而前端只能"兜不住 OOM"。

### P1-1 纯 JS SHA-256 分支**永远不会被跑到** = 写了也永远绿

D-4 #11 只断言 `sha256Hex('abc') === ba7816bf…`（单块、3 字节）。但：
- 真机/桌面默认走原生 `crypto.subtle`，**纯 JS 分支在正常测试路径里一次都不会执行**；
- 多块（>1 个 64 字节分组）、尾部填充、UTF-8 多字节边界全靠对拍才抓得到，3 字节向量抓不到。

**必改**：① 加一个显式开关（`?hash=js` 查询参或 `localStorage.mb_force_js_hash`），测试里强制走纯 JS；② 对拍集合至少三条：`'abc'`（单块）、`'a'.repeat(1000)`（多块）、`new Uint8Array([0,255,128,...])`（非文本）；③ 原生与纯 JS 两条路径**都要跑一遍同样的三条断言**（同 hex 输出）。
另：不按文件大小切换实现（原生优先、纯 JS 兜底），但纯 JS 分支必须**分块 + 让出主线程**（每 1MB `await new Promise(r=>setTimeout(r))`），否则 10 张 5MB 图会把 UI 卡死；单文件 ≥8MB 建议直接标「文件过大，未预检」而不是硬算。

### P1-2 「前 1MB + size」折中：**否决**（同意你的倾向，但理由要更硬）
它把 exact 语义降级成"前缀相同"，而 5.3 又用 exact 命中来**决定要不要建卡**⇒ 前缀碰撞会丢掉真实文件。另外它与 F4「前端不得自成第二份判定」冲突：前端用弱判据说"已导入过"，服务端全量判据说"没有"，用户看到的就是系统自相矛盾。

### P1-3 D-4 #5 的"改前 must-be-0 基线"：**没有现成基线，必须先量**

我核了：`tests/verify-ui.mjs:140-151` 那条 375 横滚断言只覆盖 **`?tab=card`（资料卡）** 的三个 tab（临床指标总览/动态趋势/全病程原件轴），**不覆盖资料录入页（`?tab=intake`）**，所以 ① 段在 375 的基线**目前无人测量**。

**给一条不碰真库/5174 的量法**（实现方执行，与 D-5 口径一致）：

### P1-4 F4 的 `sec` 切换会闪（你的怀疑成立，且 UI 过渡治不了）

`IntakePage.jsx:126-140` 用 `intersectionRatio` 取最大值决定 `sec`，`rootMargin: '-96px 0px -55% 0px'`；① 与② 交界处 ratio 会来回越过阈值 ⇒ `sec` 抖动 ⇒ 固定栏反复显隐。

**改判定，不是加过渡**：把"是否显示"从 `sec` 状态改成**几何单调量**——用 `#sec-upload` 的 `getBoundingClientRect().bottom > 0`（或 `< innerHeight * 0.6`）判：滚出 ① 就隐藏、滚回就出现，天然无抖动。CSS 过渡只解决"渐隐渐现"，解决不了"在阈值上抖"。

## 3. 八条必攻击点逐条回答

**1. 「批内命中不建卡 / 对库命中建卡」的不对称合不合理？——合理，但要补三条前提。**
不对称的正当性在于**信息量不同**：批内重复 = 同一字节、同一批次、同一会话，零信息增量（用户仍有一张卡可用）；对库重复 = 那条旧记录可能已改过/删过/入库过，"上次导的那一份"本身是有信息量的，用户要能看见。
但必须补：① **可见性**——批内跳过要给 `message.warning` + `pushLog` + **顶部计数**（否则用户"选了 3 张怎么只有 2 张"永远无解）；② **文案**用「这张图本次已选过」，不要用"文件"（避免暗示文件名判定）；③ **降级态禁跳**（P0-1）。
若你更想统一成"两边都建卡+打 Tag"：也可以，但要在卡片上把两种 Tag 文案分死（已在 F3 做了），代价是用户要多手动移一次。**两种都可接受，选一种写死即可**——我推荐保留你的不对称 + 上面三条。

**2. 纯 JS SHA-256 三个子问题。**
① **不按大小切换实现**：原生可用就用原生（任何大小），只在不可用时走纯 JS。真正要按大小处理的是**纯 JS 分支**：分块 + 让出主线程；单文件 ≥8MB 记「未预检」。
② **"前 1MB+size"否决**（P1-2）。
③ **要加硬约束**：「不许引入第三方哈希依赖（`crypto-js`/`js-sha256`/`spark-md5` 等）」——理由不是洁癖，而是这些会进 `web/dist-next` 且与「不另起体系」冲突；同时给 `sha256Hex` 一个**纯函数 + 三条对拍**（P1-1）。另注意 `crypto.subtle` 缺失时纯 JS 是**同步阻塞**的，必须 `await` 让出。

**3. D-4 #5 改前基线：必须先量，且现有测试不覆盖 ① 段。** 见 P1-3（含量法与"改前已红则降级为不得变差"）。

**4. C-9 挂起与 D-1 #4「上限 4」矛盾：成立，且比你担心得更实**——`doStitch >= 2` 是**实质放行**，不是措辞问题。见 P0-2（改成 `MAX_SELECT = 2` + `=== MAX_SELECT`）。

**5. D-4 #8/#9 的夹具能不能用 5194 + 副本库做？——能，但两条方法不同。**
- **#8 批内重复**：**不需要库里有什么**。Playwright 直接给 Dragger 的 hidden input 传两个**同字节、不同文件名**的 payload（`setInputFiles([{name:'a.jpg',...},{name:'a (1).jpg',...}])`），断言 `items.length` 只 +1 且出现提示。仍需要 5194 + 副本库，因为页面启动会 `loadReports()`。
- **#9 对库重复**：**不能**靠"库里已有真报告"（我们拿不到它的图片字节去复现同 sha256）。做法：**手改副本库**注入一条最小记录——`lib/reportStore.mjs:19` 的 `EMPTY()` 说明只认四个字段，所以副本 `reports.json` 写成
  `{"version":2,"reports":[{"id":"rep_fixture","sha256":"<夹具图 sha>","reportDate":"2026-01-01","reportType":"lab","rows":[]}],"trashed":[],"audit":[]}`。
  **不需要另造 blobs**：`attachBlobIds` 找不到 blob 只会让 `hasImage:false`，不影响 `sha256` 比对（列表接口 `server.mjs:1005-1013` 的 `...r` 展开即带 `sha256`）。夹具图的 sha256 在同一脚本里现算（node `crypto`）再写进副本库，避免手抄错。

**6. `sec` 抖动导致固定栏闪：必须改判定逻辑，UI 过渡不够。** 见 P1-4（改用 `#sec-upload` 的 `bottom` 这种单调量）。

**7. v0.2 还有没有 r1 §4 标 ⚠️/❌ 而未落地的？——没有，全部落地**（§1 逐条核）。但**新增**了 2 条 P0 + 5 条 P1（§2）。另有一处轻微不一致：修订说明写「`selected` 上限 4」，C-9 又挂起——即 P0-2；以及 D-4 #6 用 `>= 8px` 是**唯一**把数值写进判据的地方，别的都写了"待 UI 定"；spec 回来后要把 #6 的 8px 与其对齐（否则两处数值会各自漂移）。

**8. UI 规格未回是否必须先到位？——不必直接挂起全部；按"逻辑先做、视觉等数值"切分**（§0 表 + P1-5）。具体：C-5 准予；C-1/C-2/C-3/C-4/C-7/C-8/C-13 挂起等 spec，**spec 到了同一批放行**，不要拆成"先做一版再改一版"。若 Manager 坚持本轮一次做完七项，那等价于**spec 是开工前置**——那时才需要写进 r3 前置条件；两种都能接受，选一种写死。

## A-3 缺口 3 / addendum 必攻击点 3：**A1 与 A1b 都分不出 sticky 和 static —— 你们写的证伪会失败**

规格 §8 的两条：
- **A1**：滚到底后 `last.rect.bottom <= bar.rect.top + 0.5`；
- **A1b**：`scrollable ? |innerHeight - bar.rect.bottom| <= 1 : bar.rect.bottom <= innerHeight + 0.5`；
- **证伪要求**：把 `position: sticky` 改成 `static` ⇒ **A1 必红**。

**这条证伪不成立**：滚到**最大滚动位置**时，文档底边与视口底边对齐，而 `.mb-batchbar` 是最后一个元素 ⇒ 无论 `sticky` 还是 `static`，`last.bottom <= bar.top` 与 `bar.bottom ≈ innerHeight` **同时成立**。也就是说 A1/A1b 对"sticky vs static"**没有分辨力**，照你们写的证伪跑下去，实现方会看到"改成 static 也是绿的"，然后要么以为断言写错、要么把断言放宽。

**改法（一条即可分辨）**：把量测点从"滚到底"移到**中途**——
```js
// 中途滚动位置：documentElement.scrollTop = maxScroll * 0.5
const mid = document.documentElement.scrollTop;
assert(Math.abs(innerHeight - bar.rect.bottom) <= 1, 'sticky 贴底');   // static 时 bar 远在视口下方 ⇒ 必红
```
理由：sticky 在"自然位置在视口下方"时被拉到底边；static 时它就老老实实待在内容末尾（视口外）。**这是唯一能把两者分开的判据**。建议 A1 改成"中途贴底 + 到底不遮内容"两条，把证伪从 A1 挪到"中途贴底"那条。

## A-4 缺口 2（spec 选 (a) vs 计划选 (d)）：**spec 必须出 v1.1，否则实现方照规格会把 r1 P0-2 原样做回来**

1. **纯 JS 分支必须有强制入口**（否则正常路径只跑原生，纯 JS 一次都不会被执行 = 写了也永远绿）：加 `?hash=js` 开关，测试里强制走一遍，**原生与纯 JS 各跑同一组三条向量**（`'abc'`、`'a'.repeat(1000)`、非文本字节）。
