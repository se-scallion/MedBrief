## 3. 三档裁定（留 / 砍 / 延后+触发条件）

| 裁定 | 项 | 理由 |
|---|---|---|
| **留（MVP）** | **U1 提交**（已修未提交）、**U2 提交**（同上）、**U3 账号页 375 溢出**、**U4 弹窗超高**、**U5 顶栏 44 热区**、**U7 刻度 8→9** | 前两条是"已修完只差提交"；U3/U4 属"功能不可用"级；U5/U7 是触控与可读性硬线（<44 / <10px） |
| **砍** | 「统一设计系统 / 重构卡片体系 / 换图库」类建议 | 用户明确不要越界项；且与本轮缺陷无因果关系 |
| **延后（+触发条件）** | U6 打印弹窗内距（触发：用户再次报"打印件边距大"，或打印件要对外发送）· U8 圆角混用（触发：本轮 MVP 落地后做一次全站 token 盘点）· U9/U10 热区批量（触发：真机点不中的具体页面被点名）· U11 截断口径（触发：与实现方对齐时顺手改文案）· U12 空态引导（触发：新用户首次进入这三页的反馈）· U13/U14（触发：下一轮巡检合并处理） | 都是"改善"而非"不可用"，且改动面大（U9/U10 涉及 50–200 个元素），一次性铺开风险高于收益 |

## 6. 采集与数字的复跑方式（供审核者核对，不是让实现方照抄）

- 独立实例：`PORT=519x MEDBRIEF_AUTH=on MB_SESSION_SECRET=<32字符> MEDBRIEF_REPORTS_FILE=<真库> MEDBRIEF_DATA_DIR=<临时目录（内含 intake/patient.json 副本）>`；自建 admin → `POST /api/auth/login` 取 `mb_session` → Playwright `addCookies`。
- 每页采集：`scrollWidth − clientWidth`、`font-size < 12` 的正文级文本数、`<44px` 的按钮/链接数、`.ant-card/.ant-btn/.ant-tag` 的 `border-radius` 分布、`svg text` 的渲染高。
- **已知边界**：① 巡检在他人工作树有未提交改动时进行（U1/U2 因此是"已修未提交"）；② `SourceModal` 的原件图在本次夹具里为空（该报告无 blob）⇒ U2 的媒体左缘判据只在"有原件"的报告上成立，本次用 `title/工具栏/内容` 三缘替代验证；③ 1440 趋势列为 **3**（`minmax(min(380px,100%),1fr)` 的自然结果），不是 2 —— 审核若要求 2 列，请另行出规格，不在本轮 MVP 内。
