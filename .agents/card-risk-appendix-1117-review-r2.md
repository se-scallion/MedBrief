⇒ 三处合计 **"危险度" 出现 ≥4 次**（提示语 2 次 + 容器名 2 处），而判据要求全文件 `grep -c` **= 1**。**这条断言写下来的当天就是红的**，与 r1 在账号系统线抓到的那条"`/index.html` 必须 403"是同一类：**判据永远红 ⇒ 一定被放宽 ⇒ 一定变永远绿**，而它守的是医疗红线第一条（不写诊断结论）。

**注意：这不是"作者写错了一个词"**——`r1 §5.2` 我给的原文是"不得出现'高危/中危/低危'作为**结论性字样**，判据 `grep -c`=1"，**"危险度"是我在散文里提到、没进 `grep` 模式串**。作者把"危险度"一起并进禁用集（本意是更严），结果与"必须告诉医生'这不是危险度结论'"这个提示语直接对撞。**这半个锅在我**：我那段写法本身埋了坑（用一个 `grep -c` 既当"禁用词"又当"允许清单"，而两类文案共用同一批字）。

**改法（二选一，都各一行，推荐 (a)）**：

**(a) 让禁用集与文案分离**——把两处文案里的"危险度"换成不撞词的说法，判据不变：
- 提示语 → "以下为分层判据所需的原始证据，**不等同于危险分组结论；分组由医生结合指南判断。**"
- 容器③ → "`分期/分组（原文）`"
- 判据保持 `grep -c '高危\|中危\|低危\|危险度' lib/intakeCard.js = 1`（仅剩被改名的旧格名；若格名也改成"分子与遗传学标签"，则该值应为 **0**，判据相应改成 `= 0`——**这一点必须一起写死，否则改名当天判据又红**）。

**(b) 判据改为"禁结论句式"**（不禁名词）：
```bash
grep -Ec '(定为|判断为|属|归为|系)(高危|中危|低危)' lib/intakeCard.js   # 必须 = 0
grep -n  '危险度\|高危\|中危\|低危' lib/intakeCard.js                  # 允许清单，逐条必须是人可解释的固定文案
```
(b) 更贴红线原意（禁的是"下结论"，不是"提到这个词"），但要求"允许清单"每次人工过目——比 (a) 弱。

**我的取向**：(a) 为主。因为"医生看到'危险度'三个字就以为是结论"这个风险，被"文案里必须说'这不是危险度结论'"这件事部分抵消了；真正要防的是**卡片上出现"高危/中危/低危"字样**。所以判据最终形态建议：**`grep -c '高危\|中危\|低危' = 0`**（不含"危险度"），另加一条 `grep -c '危险度' = 2`（提示语与容器名各一，位置固定、人可解释）。**两条分开，一条管结论、一条管允许清单**，不要合成一个数。
